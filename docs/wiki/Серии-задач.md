# Серии задач

**Серия** даёт задачам проекта номера 1, 2, 3… — ссылка `ПРЕФИКС-номер`, например `TSK-5`. Внутри Tasker задачи по-прежнему связаны по Guid; номер — удобное имя для людей, коммитов и веток.

- **Модель.** Серия принадлежит проекту, в проекте их может быть несколько; у неё есть название и **префикс** (только латинские буквы и цифры, до 20 символов, регистр важен: `TSK` и `tsk` — разные серии; уникален в проекте). Серия не связана с типом задачи. Задача может быть без серий, в одной или в нескольких — тогда у неё по номеру в каждой. Файл серии — `series/<id>.yaml` в папке проекта, номера задачи — список `series: [{seriesId, number}]` в её файле; в БД — таблицы `series` и `task_series_numbers` (**миграций нет: существующие БД нужно пересоздать**).
- **Номер новой записи** в серии = наибольший номер серии среди задач проекта + 1 (берётся из кэша, отдельного счётчика нет). Выбор номера и запись задачи атомарны (`IWriteScope.Exclusive`: файлы — `write.lock` и сверка индекса задач проекта перед выбором номера, чтобы учесть только что принесённый `git pull`; БД — транзакция с повтором при нарушении уникального индекса `(проект, серия, номер)`). Удалили задачу с самым большим номером — её номер выдадут заново.
- **Ссылки.** Задачу можно указать Guid или `ПРЕФИКС-номер` (разбор по последнему дефису, регистр важен, ведущие нули допустимы). Если у ссылки несколько задач (дубликат номера), поиск вернёт все.
- **Дубликаты номеров** возникают при слиянии веток git: обе создали задачу с номером 5 — файлы разные, конфликта git нет. Обе задачи остаются в списках и помечены «конфликт номера»; порядок в дубликате — по номеру, затем по Guid (по тексту Guid, одинаково во всех слоях). Решаются вручную (`tasker series renumber-task`) или `tasker cleanup --resolve-conflicts`: номер сохраняет самая ранняя задача (`createdAt`, при равенстве — Guid), остальные получают максимум + 1 в том же порядке.
- **Дубликаты префиксов** (две серии с одним префиксом после слияния) не блокируют работу: ссылки задач идут по id серии. После сверки в консоль и лог демона идёт ошибка «требуется переименование серии»; исправляется `tasker series update <серия> --prefix …`.
- **Недействительные ссылки.** Серию с задачами удалять можно: в той же операции из задач убираются ссылки на неё (серия удаляется первой). Ссылка на серию, которой нет (ветка удалила серию, другая добавила в неё задачу), считается недействительной: номер не показывается, `cleanup` убирает ссылку из файла.
- **Сверка ничего не пишет.** `tasker sync`, наблюдатель, git-хуки и демон только **сообщают** (дубликаты номеров и префиксов, недействительные ссылки на серии, недействительные связи между задачами, циклы связей, нечитаемые файлы серий) и подсказывают `tasker cleanup`. Проблемы связей `tasker sync` выводит отдельным блоком «Link problems in project …», демон пишет в лог отдельное предупреждение «links need attention» (как и про серии — один раз на состояние); в JSON сверки это поля `tasksWithInvalidLinks`, `unreadableLinkFiles` и `linkCycles` проекта (циклы связей, которые запретил бы `allowCycles`: `cleanup` их не удаляет, только сообщает с подсказкой `task unlink`). Пишет только `cleanup`.
- **`tasker cleanup`** для каждого проекта: убирает недействительные ссылки на серии и **недействительные связи между задачами** (на задачу или тип связи, которых нет: после слияния веток один удалил задачу или тип, другой добавил на них связь); `--resolve-conflicts` ещё решает дубликаты номеров; `--dry-run` показывает, что изменится; `--check` ничего не пишет и завершается кодом 2, если есть что чистить (для CI); `--json` — для скриптов (по проекту: `changes[]`, `remainingNumberConflicts[]`, `prefixConflicts[]`, `skipped`, `skipReason`, `linksSkipReason`, `linkCycles[]` (циклы связей: только сообщаются, `cleanup` их не удаляет; `--check` при них даёт код 2); у убранной связи `kind: "removedInvalidLink"`, `linkTypeId`, `linkTargetId`, `seriesId` пуст). Ничего не трогает, если среди файлов серий есть нечитаемые (конфликт git): нечитаемая серия выглядела бы несуществующей, и её ссылки были бы стёрты; реальный запуск при этом завершается кодом 1. Так же и со связями: пока среди файлов задач или типов связей есть нечитаемые, связи не проверяются (нечитаемая задача или тип выглядели бы несуществующими, и связи на них были бы стёрты) — серии при этом очищаются как обычно, а причина попадает в `links skipped` / `linksSkipReason`, код выхода 1. Не пишет, пока идёт слияние, rebase, cherry-pick или revert (`--dry-run` и `--check` работают). Работает напрямую с папкой или SQLite, демон не нужен.
- **Принятые последствия.** Ссылки на номер вне Tasker (сообщения коммитов, названия веток, PR, чаты) ломаются при переименовании номера или префикса и при повторной выдаче освободившегося номера. `TSK` и `tsk` легко перепутать.

Команды CLI (сначала действие, потом серия, потом номера и имена):

```
tasker series create <название> --prefix <префикс>
tasker series list | get <серия> | update <серия> [--name] [--prefix] | delete <серия>
tasker series add-task <серия> <задача>
tasker series remove-task <серия> <номер>
tasker series renumber-task <серия> <задача> [--to N]     # без --to — следующий свободный
tasker task create <заголовок> --type … [--series <серия>]...
tasker task get|update|delete <Guid или ПРЕФИКС-номер>
tasker task list [--series <серия>] [--flat]              # дочерние задачи эпика — под ним с отступом (--flat — плоско); строка: ПРЕФИКС-номер  статус  тип  заголовок (напр. TSK-12  Бэклог  Фича  Миграции БД); без серии вместо ссылки короткий id (первые 8 символов Guid, как в имени файла); тип не найден — ячейка типа пустая; колонки выровнены по самой широкой ячейке на выведенной странице (ширина — в знаках терминала: кириллица, эмодзи, CJK), разделитель — два пробела, заголовок не дополняется; так же устроены `task links`, `board tasks`, `board show` и списки `… list` (в них первая колонка — короткий id)
tasker cleanup [--resolve-conflicts] [--dry-run] [--check] [--json]
```

`<серия>` — Guid или префикс. Неоднозначная ссылка (дубликат номера) в `task update/delete` и в командах серии отклоняется со списком id; `task get` показывает все задачи.

API (`/api/projects/{projectId}/…`): `GET/POST /series`, `GET /series/health`, `GET/PATCH/DELETE /series/{id}`; `POST /tasks` принимает `seriesIds`, задачи отдают `seriesNumbers: [{seriesId, number}]`; `GET /tasks?seriesId=`, `GET /tasks/resolve?ref=TSK-5`, `POST /tasks/{id}/series {seriesId, version}`, `DELETE /tasks/{id}/series/{seriesId}?version=`, `POST /tasks/{id}/series/{seriesId}/renumber {to?, version}`. События `series` приходят в потоке SSE рабочей области.

MCP: `list_series`, `get_series` (по id или префиксу), `create_series`, `update_series`, `delete_series`, `series_health`, `add_task_to_series`, `remove_task_from_series`, `renumber_task`, `find_tasks_by_reference`; `create_task` принимает `seriesIds`, `list_tasks` — `seriesId`. Код ошибки (`[in_use]`, `[modified]`, …) стоит в начале текста ошибки.
