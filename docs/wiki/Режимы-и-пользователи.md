# Режимы и пользователи

Режим задаёт хост в коде, а не конфиг:

| | Tasker.Server | Tasker.Desktop |
|---|---|---|
| Хранилище | только БД (SQLite / Postgres) — с файлами сервер не стартует | у каждой вкладки своё: папка (файлы) или файл SQLite |
| Пользователь | имя, почта, пароль | только имя |
| Вход | JWT: `Authorization: Bearer <token>` | нет |
| Доступ к проектам | участники проекта и админы | все проекты |

Пароли и участники проектов хранятся только в БД: хэши паролей в git-репозитории с `.tasker` не нужны. Пользователи десктопа в режиме `Files` лежат в `.tasker/users/<id>.yaml`.

### Сервер: вход и права

- **Первый пользователь** регистрируется сам (`POST /api/auth/register`) и становится администратором. После этого регистрация закрыта: пользователей создаёт админ.
- **Вход** — `POST /api/auth/login` с `login` (имя или почта) и `password`. В ответе приходят `accessToken`, `accessTokenExpiresAt`, `refreshToken`, `refreshTokenExpiresAt` и `user`.
- **Access-токен** (JWT) — короткий, по умолчанию 15 минут, передаётся в `Authorization: Bearer`.
- **Refresh-токен** — по умолчанию 30 дней, меняется на новую пару через `POST /api/auth/refresh {"refreshToken"}`. Каждый обмен продлевает срок, поэтому активный пользователь не разлогинивается.
  - **Одноразовый.** При обмене гасится, выдаётся новая пара.
  - **Защита от кражи.** Повторное предъявление уже использованного refresh-токена, в том числе параллельный обмен одного и того же токена, отзывает всю сессию: и вору, и владельцу нужно войти заново. Поэтому клиент должен обменивать токен из одного места (одна очередь на все вкладки).
  - **Хранится только SHA-256** токена: утечка базы не даёт рабочих refresh-токенов.
- **Выход** — `POST /api/auth/logout {"refreshToken"}` отзывает эту сессию. Уже выданный access-токен действует до своего короткого срока.
- **Отзыв токенов.** После смены пароля или удаления пользователя его токены сразу перестают приниматься, не дожидаясь срока.
- **Админ** создаёт, меняет и удаляет пользователей, выдаёт права админа и видит все проекты. Удалить себя и снять права с последнего админа нельзя.
- **Обычный пользователь** меняет только своё имя, почту и пароль (со старым паролем), создаёт проекты.
- **Проекты.** Видны только их участникам. Создатель проекта становится участником. Участники-люди добавляют и убирают других; последнего человека убрать нельзя. Чужой проект отвечает 404, как несуществующий, чтобы не раскрывать, какие проекты есть на сервере.
- **Ключ подписи JWT** (от 32 байт) задаётся через `TASKER_AUTH_CONFIGS_SIGNING_KEY` или `--jwtkey` и в репозитории не хранится. Если не задан, при старте генерируется временный ключ с предупреждением в логе: для разработки этого достаточно, но все токены перестают действовать после перезапуска. В продакшене ключ задавать обязательно.
- **Пароль** — от 8 символов, хранится в виде хэша PBKDF2 из ASP.NET Identity.

API пользователей:

| Путь | Методы |
|---|---|
| `/api/auth/register`, `/api/auth/login`, `/api/auth/refresh`, `/api/auth/logout` | `POST` — без токена (только сервер) |
| `/api/auth/registration` | `GET` — без токена: `{"open": true}`, пока нет ни одного пользователя (только сервер) |
| `/api/auth/me` | `GET` — текущий пользователь (только сервер) |
| `/api/users`, `/api/users/{id}` | `GET`, `POST` (создать), `PATCH`, `DELETE` |
| `/api/users/{id}/password` | `POST {"currentPassword", "newPassword"}` (только сервер) |
| `/api/projects/{projectId}/members` | `GET`, `POST {"userId"}`; `DELETE /members/{userId}` (только сервер) |
| `/api/agents`, `/api/agents/{id}` | `GET`, `POST {"username"}`, `PATCH`, `DELETE` — агенты (см. ниже) |
| `/api/agents/{id}/tokens` | `GET`, `POST {"name", "expiresAt"?}`; `DELETE /tokens/{tokenId}` — токены агента (только сервер) |

Нет прав — `403 {"error": "..."}`, нет или неверный токен — `401`.
