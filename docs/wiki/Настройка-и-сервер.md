# Настройка и сервер

Tasker запускается в трёх видах: консоль `tasker`, десктоп (окно с вкладками) и сервер (общий веб-сервис с входом). Настройки задаются переменными окружения и аргументами; файлы конфигурации не используются.

## Настройки

Аргумент важнее переменной окружения; не задано нигде — значение по умолчанию. На опечатку в имени хост выдаёт предупреждение с подсказкой.

| Переменная | Аргумент | Что задаёт | По умолчанию |
|---|---|---|---|
| `TASKER_DB_CONFIGS_POSTGRES_CONNECTION_STRING` | `--postgres`, `--db` | строка подключения Postgres (сервер) | нет |
| `TASKER_DB_CONFIGS_SQLITE_FILE` | `--sqlite` | файл SQLite | нет |
| `TASKER_FILES_CONFIGS_PATH` | `--files` | папка с `.tasker` (только десктоп) | нет |
| `TASKER_AUTH_CONFIGS_SIGNING_KEY` | `--jwtkey` | ключ подписи токенов, от 32 байт | временный, токены сгорают при перезапуске |
| `TASKER_AUTH_CONFIGS_ACCESS_TOKEN_LIFETIME` | — | срок access-токена | `00:15:00` |
| `TASKER_AUTH_CONFIGS_REFRESH_TOKEN_LIFETIME` | — | срок refresh-токена | `30.00:00:00` |
| `TASKER_MCP_CONFIGS_PORT` | `--mcpport` | порт MCP десктопа | из глобальных настроек (`5719`) |
| `TASKER_HOME` | — | каталог данных Tasker | см. таблицу ниже |
| `TASKER_PROJECT` | `-p` | проект по умолчанию для консоли | единственный проект |
| `TASKER_WIDTH` | `--width` | ширина строки списков консоли | ширина терминала |
| `TASKER_LANG` | `--lang` | язык справки `tasker manual` | язык по умолчанию |
| `TASKER_MCP_SUPERVISOR` | — | бесшовное обновление демона (`1`), на Windows по умолчанию выключено | см. [Платформы](Платформы) |
| `TASKER_SERVICE_LABEL`, `TASKER_SERVICE_DIR` | — | имя и каталог службы автозапуска | `com.tasker.mcp` (macOS), `tasker-mcp.service` (Linux), `Tasker MCP` (Windows) |

Порт демона MCP читается и меняется командами `tasker mcp config` и `tasker mcp port <порт>` (после смены нужен `tasker mcp restart`). Остальные аргументы ASP.NET Core (`--urls`, `--environment`) работают как обычно; сервер в разработке слушает `http://localhost:5156`.

Каталог данных Tasker (глобальные настройки `settings.json`, журналы `logs`, состояние демона `mcp`):

| macOS | Linux | Windows |
|---|---|---|
| `~/Library/Application Support/Tasker` | `~/.local/share/Tasker` | `%LOCALAPPDATA%\Tasker` |

## Режимы

| | Сервер | Десктоп | Консоль |
|---|---|---|---|
| Хранилище | только БД: Postgres или SQLite; без настройки — SQLite в памяти, данные пропадают при перезапуске | у каждой вкладки своё: папка `.tasker` или файл SQLite (`--files`, `--sqlite`) | папка (`-w`, по умолчанию текущая) или файл SQLite (`--sqlite`) |
| Пользователь | имя, почта, пароль | только имя | имя ОС, меняется `tasker whoami <имя>` |
| Вход | да, JWT | нет | нет |
| Проекты | видят участники и админы | все | все |

Заданные одновременно папка и БД, Postgres и SQLite, а также `--files` на сервере — ошибка при старте. Хранилища: [Хранение и git](Хранение-и-git); консоль: [Консоль](Консоль); интерфейс: [Интерфейс](Интерфейс).

## Пользователи, вход и права

- Первый пользователь регистрируется сам (`POST /api/auth/register`) и становится админом; потом регистрация закрыта, пользователей создаёт админ. Пароль — от 8 символов.
- Вход — `POST /api/auth/login` (`login`: имя или почта, `password`). Ответ содержит access-токен (JWT, в заголовок `Authorization: Bearer`) и refresh-токен.
- Refresh-токен одноразовый: `POST /api/auth/refresh` меняет его на новую пару. Повторное предъявление использованного токена отзывает всю сессию, поэтому обменивайте его из одного места. `POST /api/auth/logout` отзывает сессию.
- Админ управляет пользователями и видит все проекты; себя удалить и снять права с последнего админа нельзя. Обычный пользователь меняет своё имя, почту и пароль и создаёт проекты.
- Проект виден только участникам; чужой проект отвечает `404`. Участников добавляют и убирают участники-люди, последнего человека убрать нельзя.
- Нет прав: `403`; нет или неверный токен: `401`.

## Агенты и токены

Агент — пользователь для LLM, работающий только через MCP. Его создаёт человек (владелец), админ видит всех агентов; агент не может быть админом и управлять пользователями, агентами и участниками. Как подключить агента: [MCP и агенты](MCP-и-агенты).

| Режим | Как агент представляется |
|---|---|
| Сервер | токен `tsk_…` создаётся для агента, значение показывается один раз; подключение к `/mcp` с заголовком `Authorization: Bearer tsk_…`. У агента может быть несколько токенов со сроком или без; список показывает начало токена и время последнего использования |
| Десктоп, демон | токен не нужен; агента выбирает заголовок `X-Tasker-Agent: <id>`, без него вызовы идут от агента `agent` |

Агента добавляют в проект участником, как человека. Токен агента не принимается в REST, JWT людей не принимается в MCP.

## REST API

Адрес на сервере: `/api/…`, на десктопе: `/w/<папка>/api/…`. Списки постраничные (`offset`, `limit`); изменения несут `version` ([Хранение и git](Хранение-и-git)). Внутри проекта пути начинаются с `/api/projects/{projectId}`.

| Метод и путь | Что делает |
|---|---|
| `GET, POST /projects`; `GET, PATCH, DELETE /projects/{id}` | проекты; `GET /projects/{id}/stats` — сколько чего в проекте |
| `GET, POST /…/tasks`; `GET, PATCH, DELETE /…/tasks/{id}` | задачи; фильтры `statusId`, `typeId`, `seriesId`, `field=Имя=значение`, сортировка `sort` |
| `GET, POST, DELETE /…/tasks/{id}/links` | связи задачи |
| `GET, POST /…/{statuses, status-sets, task-types, link-types, fields, enums, boards, series}`; `GET, PATCH, DELETE …/{id}` | справочники проекта |
| `POST /…/boards/{id}/columns/{columnId}/move` | перенести задачу в колонку доски |
| `POST, GET, DELETE /…/{tasks, statuses, …}/{id}/lock`; `GET /…/locks` | блокировка на время правки |
| `GET, POST /projects/{id}/members`; `DELETE …/members/{userId}` | участники проекта (сервер) |
| `GET, POST, PATCH, DELETE /users`, `/agents`; `…/agents/{id}/tokens` | пользователи, агенты и их токены |
| `POST /auth/register, login, refresh, logout`; `GET /auth/me` | вход (сервер) |
| `GET /w/<папка>/api/events` | поток событий SSE для обновления вкладок (десктоп) |

Ограничения: Postgres не проверялся; схема БД создаётся при старте и не мигрирует.
