# Настройка и сервер

Tasker запускается в двух видах: консоль `tasker` с демоном MCP и сервер (общий веб-сервис с входом). Настройки задаются переменными окружения и аргументами; файлы конфигурации не используются.

## Настройки

Аргумент важнее переменной окружения; не задано нигде — значение по умолчанию. На опечатку в имени хост выдаёт предупреждение с подсказкой.

| Переменная | Аргумент | Что задаёт | По умолчанию |
|---|---|---|
| `TASKER_DB_CONFIGS_POSTGRES_CONNECTION_STRING` | `--postgres`, `--db` | строка подключения Postgres (сервер) | нет |
| `TASKER_DB_CONFIGS_SQLITE_FILE` | `--sqlite` | файл SQLite | нет |
| `TASKER_AUTH_CONFIGS_SIGNING_KEY` | `--jwtkey` | ключ подписи токенов, от 32 байт | временный, токены сгорают при перезапуске |
| `TASKER_AUTH_CONFIGS_ACCESS_TOKEN_LIFETIME` | — | срок access-токена | `00:15:00` |
| `TASKER_AUTH_CONFIGS_REFRESH_TOKEN_LIFETIME` | — | срок refresh-токена | `30.00:00:00` |
| `TASKER_HOME` | — | каталог данных Tasker | см. таблицу ниже |
| `TASKER_PROJECT` | `-p` | проект по умолчанию для консоли | единственный проект |
| `TASKER_WIDTH` | `--width` | ширина строки списков консоли | ширина терминала |
| `TASKER_REFRESH_SECONDS` | — | период автообновления экрана просмотра в `tasker -i`, секунды | `10` |
| `TASKER_LANG` | `--lang` | язык справки `tasker manual` | язык по умолчанию |

Порт демона MCP читается и меняется командами `tasker mcp config` и `tasker mcp port <порт>` (после смены нужен `tasker mcp restart`). Остальные аргументы ASP.NET Core (`--urls`, `--environment`) работают как обычно.

Каталог данных Tasker (глобальные настройки `settings.json`, журналы `logs`, состояние демона `mcp`):

| macOS | Linux | Windows |
|---|---|---|
| `~/Library/Application Support/Tasker` | `~/.local/share/Tasker` | `%LOCALAPPDATA%\Tasker` |

## Режимы

| | Сервер | Консоль |
|---|---|---|
| Хранилище | только БД: Postgres или SQLite; без настройки — SQLite в памяти, данные пропадают при перезапуске | папка `.tasker` (`-w`, по умолчанию текущая) |
| Пользователь | имя, почта, пароль | имя ОС, меняется `tasker whoami <имя>` |
| Вход | да, JWT | нет |
| Проекты | видят участники и админы | все |

Заданные одновременно папка и БД, Postgres и SQLite, а также `--files` на сервере — ошибка при старте. Хранилища: [Хранение и git](Хранение-и-git); консоль: [Консоль](Консоль); интерфейс: [Интерфейс](Интерфейс).

## Пользователи, вход и права

- Первый пользователь регистрируется сам (`POST /api/auth/register`) и становится админом; потом регистрация закрыта, пользователей создаёт админ. Пароль — от 8 символов.
- Вход — `POST /api/auth/login` (`login`: имя или почта, `password`). Ответ содержит access-токен (JWT, в заголовок `Authorization: Bearer`) и refresh-токен.
- Refresh-токен одноразовый: `POST /api/auth/refresh` меняет его на новую пару. Повторное предъявление использованного токена отзывает всю сессию, поэтому обменивайте его из одного места. `POST /api/auth/logout` отзывает сессию.
- Админ управляет пользователями и видит все проекты; себя удалить и снять права с последнего админа нельзя. Обычный пользователь меняет своё имя, почту и пароль и создаёт проекты.
- Проект виден только участникам; чужой проект отвечает `404`. Участников добавляют и убирают участники-люди, последнего человека убрать нельзя.
- Нет прав: `403`; нет или неверный токен: `401`.

## Агенты и токены

Агент — пользователь для LLM, работающий только через MCP. Его создаёт человек (владелец), админ видит всех агентов; агент не может быть админом и управлять пользователями, агентами и участниками. Как подключить агента: [MCP и агенты](MCP-и-агенты).

| Режим | Как агент представляется |
|---|---|
| Сервер | токен `tsk_…` создаётся для агента, значение показывается один раз; подключение к `/mcp` с заголовком `Authorization: Bearer tsk_…`. У агента может быть несколько токенов со сроком или без; список показывает начало токена и время последнего использования |
| Демон | токен не нужен; агента выбирает заголовок `X-Tasker-Agent: <id>`, без него вызовы идут от агента `agent` |

Агента добавляют в проект участником, как человека. Токен агента не принимается в REST, JWT людей не принимается в MCP.

## API

Адрес на сервере: `/api/…`, в локальном режиме Tasker.Web (сейчас без хоста): `/w/<папка>/api/…`. Чтение — GraphQL, изменения — REST.

### Чтение: GraphQL

Один адрес: `POST /api/graphql`, тело — `{"query": "…", "operationName": "…", "variables": {…}}`. GET не поддерживается. Схема целиком — в файле [`graphql/schema.graphql`](https://github.com/SmokyOoOwizard/Tasker/blob/main/graphql/schema.graphql); по нему генерируются клиенты.

- В корне: `projects`, `project(id)`, `users`, `user(id)`, `agents`, `agent(id)`, `agentTokens(agentId)` (сервер), `me` и `registration` (сервер), `workspaceProblems` и `workspaceMcp` (локальный режим).
- Всё о проекте — поля `project(id)`: `stats`, `statuses`, `statusSets`, `taskTypes`, `fields`, `enums`, `linkTypes`, `tasks` и `taskTree` (фильтры `statusIds`, `typeIds`, `seriesIds`, `field: ["Имя=значение"]`, сортировка `sort`), `task(id)`, `resolveTasks(ref)`, `taskLinks(id)`, `taskComments(id)`, `seriesList`, `series(id)`, `seriesHealth`, `boards`, `board(id)`, `columnTasks(boardId, columnId)`, `locks`, `lock(entity, id)`, `members` (сервер). У каждого списка — `offset` и `limit`, ответ — `{totalCount, offset, limit, data}`.
- Поиск задач — `project(id).taskSearch(query, limit, statusIds, typeIds, seriesIds)`: сначала номер («133», «TSK-133», начало номера), потом заголовок, потом описание, без учёта регистра и порядка слов, с частью слова, опечатками и неверной раскладкой. У каждого результата есть `score` от 0 до 1, `field`, `match` и у совпадения в описании `snippet`. Индекс — кэш: он сверяется с хранилищем при каждом запросе, на сервере лежит в памяти, а у папки в `.tasker/.cache/search-1`.
- Нет записи — `null`. Ошибка — в `errors`: `extensions.code` (`BAD_REQUEST`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`) и `extensions.status` — код, который ответил бы REST. На сервере без входа доступна только `registration`, остальное — ответ 401.
- Подписка `workspaceChanges` (только локальный режим): что изменилось в рабочей области. Ответ — поток SSE (`text/event-stream`) на тот же `POST /api/graphql`, события `next` и `complete`. Поле `author { key name }` называет автора, если правка прошла через демон или сервер: REST — локальный человек (`local`, имя из `tasker whoami`), MCP — агент (`user:<id>`). У правок из консоли, git и вручную автора нет.

Файл схемы пишет `dotnet run --project dotnet/tools/Tasker.GraphSchema`, проверяет — тот же запуск с `--check` (его выполняет CI) и тест `GraphTests`. Схема поменялась в коде — перепишите файл и закоммитьте его вместе с изменением.

### Изменения: REST

Изменения несут `version` ([Хранение и git](Хранение-и-git)). Внутри проекта пути начинаются с `/api/projects/{projectId}`.

| Метод и путь | Что делает |
|---|---|
| `POST /projects`; `PATCH, DELETE /projects/{id}` | проекты |
| `POST /…/tasks`; `PATCH, DELETE /…/tasks/{id}` | задачи |
| `POST, DELETE /…/tasks/{id}/links` | связи задачи |
| `POST /…/{statuses, status-sets, task-types, link-types, fields, enums, boards, series}`; `PATCH, DELETE …/{id}` | справочники проекта |
| `POST /…/boards/{id}/columns/{columnId}/move` | перенести задачу в колонку доски |
| `POST, DELETE /…/{tasks, statuses, …}/{id}/lock` | блокировка на время правки |
| `POST /projects/{id}/members`; `DELETE …/members/{userId}` | участники проекта (сервер) |
| `POST, PATCH, DELETE /users`, `/agents`; `POST, DELETE …/agents/{id}/tokens` | пользователи, агенты и их токены |
| `POST /auth/register, login, refresh, logout` | вход (сервер) |

GET остаётся только у служебных адресов: `/api/health`, а у демона — `/health`, `/ready` и `/daemon/status`.

Ограничения: Postgres не проверялся; схема БД создаётся при старте и не мигрирует.
