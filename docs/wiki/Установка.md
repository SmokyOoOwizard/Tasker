# Установка

Tasker ставится из релиза — архива самодостаточной сборки (`tasker` и демон MCP `tasker-mcpd`; **.NET и права администратора не нужны**). Платформы:

| Система | Архив | Установщик | Автозапуск демона |
|---|---|---|---|
| macOS (Apple Silicon, Intel) | `tasker-<версия>-osx-arm64.tar.gz`, `-osx-x64.tar.gz` | `install.sh` | launchd (агент пользователя) |
| Linux (glibc: Debian, Ubuntu, Fedora, Arch…; x64, arm64) | `-linux-x64.tar.gz`, `-linux-arm64.tar.gz` | `install.sh` | systemd (`--user`) |
| Windows 10 1809+ (x64, arm64) | `-win-x64.zip`, `-win-arm64.zip` | `install.ps1` | Планировщик заданий (задача пользователя) |

Alpine (musl) пока не поддерживается. Linux нужна библиотека ICU (`libicu`; на Debian/Ubuntu — `apt install libicu-dev`, обычно уже есть): установщик предупредит, если её нет. Десктоп (`Tasker.Desktop`) в релиз не входит — Windows-упаковка десктопа отдельной задачей (TSK-121).

### Установка одной командой

macOS и Linux — распаковать архив и запустить `install.sh` из него (или указать архив/адрес):

```bash
tar -xzf tasker-0.1.0-osx-arm64.tar.gz && tasker-0.1.0-osx-arm64/install.sh   # из распакованного релиза
install.sh --from tasker-0.1.0-linux-x64.tar.gz                                # из архива или из каталога с готовой сборкой
install.sh --url https://<адрес релизов>/tasker-0.1.0-linux-x64.tar.gz         # скачать (рядом должен лежать …tar.gz.sha256: сумма проверяется)
```

Windows (PowerShell 5.1 или 7), в распакованном архиве:

```powershell
Expand-Archive tasker-0.1.0-win-x64.zip .; .\tasker-0.1.0-win-x64\install.ps1   # или: .\install.ps1 -From tasker-0.1.0-win-x64.zip
```

Адрес, откуда качать релизы (чтобы заработало `curl -fsSL <адрес>/install.sh | bash`), пока не выбран: архивы собирает `scripts/release.sh`, публикация — отдельное решение. Повторный запуск — **обновление**; `--uninstall` / `-Uninstall` — **удаление**.

### install.sh (macOS и Linux)

```bash
install.sh                         # релиз, с которым пришёл скрипт (рядом каталог app/): в ~/.local
install.sh --from ФАЙЛ.tar.gz|КАТАЛОГ    # из архива или каталога с готовой сборкой (tasker и tasker-mcpd в нём или в его app/)
install.sh --url АДРЕС.tar.gz [--no-verify]   # скачать; АДРЕС.tar.gz.sha256 проверяется (--no-verify: без файла суммы)
install.sh --from-source           # собрать из исходников репозитория (для разработчиков; нужен .NET SDK 10): как делал прежний установщик только для macOS
install.sh --from-source --framework-dependent   # маленькая сборка (~50 МБ): нужен .NET 10 runtime
install.sh --from-source --no-daemon             # только консольная утилита, без демона MCP
install.sh --prefix ~/tools        # другой каталог: ~/tools/share/tasker/app и ~/tools/bin/tasker
install.sh --add-to-path           # дописать <prefix>/bin в PATH профиля оболочки, если его там нет
install.sh --no-autostart          # не включать автозапуск демона
install.sh --no-completion         # не подключать автодополнение по Tab к оболочке (скрипты всё равно кладутся)
install.sh --restart               # работавший демон перезапустить (по умолчанию он заменяется на лету, без простоя)
install.sh --uninstall             # удалить
```

- **Что ставится.** `<prefix>/share/tasker/app/` (`tasker`, `tasker-mcpd`, библиотеки: самодостаточная сборка, около 150 МБ распакованной, ReadyToRun), `<prefix>/bin/tasker` — ссылка на `tasker`, `<prefix>/share/tasker/completions/` — скрипты автодополнения. Платформа (macOS/Linux, arm64/x64) определяется сама; сборка не для этой машины отклоняется («this build is for …»). Права администратора не нужны.
- **Безопасное обновление.** Сборка копируется во временную папку и проверяется дымовым тестом (создание проекта в отдельном каталоге данных); только после этого установка подменяется целиком. Сломанная сборка рабочую установку не трогает. Лишних файлов и старых версий не остаётся.
- **Автозапуск демона.** Если автозапуск не включён, установщик выполняет `tasker mcp autostart enable` (launchd / systemd `--user`; сразу запускает демон); включён — не трогает. Не вышло (например, в контейнере без systemd) — предупреждение с подсказкой, установка остаётся. `--no-autostart` службу не трогает. Путь к программе стабилен (`<prefix>/share/tasker/app/tasker`), поэтому служба и git-хуки (`tasker hooks install`) после обновления продолжают работать.
- **Работающий демон** переводится на новую сборку без простоя (`tasker mcp upgrade`, см. [«MCP-демон: обновление без простоя»](Демон-MCP#mcp-демон-обновление-без-простоя)). Не получилось — старый продолжает работать, перезапуск молча **не** делается: установщик печатает причину и подсказку `tasker mcp upgrade --restart`. `--restart` перезапускает по просьбе (вызовы в работе обрываются).
- **Автодополнение по Tab.** В файл оболочки (по `$SHELL`: zsh — `~/.zshrc`; bash — на Linux `~/.bashrc`, на macOS login-файл) дописывается один помеченный блок — подробности, резервная копия `.tasker-backup` и отмена в разделе [«Автодополнение по Tab»](Консоль#автодополнение-по-tab) консоли. Повторная установка блок не дублирует.
- **PATH.** Если `<prefix>/bin` не в PATH, скрипт печатает строку для профиля оболочки (zsh — `~/.zprofile`; bash — login-файл macOS или `~/.profile` на Linux); с `--add-to-path` дописывает её сам (один раз, под меткой `# tasker`).
- **Удаление** выключает автозапуск и останавливает демон (пока утилита ещё на месте), убирает ссылку (только если она ведёт в эту установку), программу, скрипты автодополнения и свой блок в файле оболочки (копия `.tasker-backup` остаётся). Данные Tasker (macOS: `~/Library/Application Support/Tasker`, Linux: `~/.local/share/Tasker`) и рабочие папки не трогаются; git-хуки остаются и без `tasker` ничего не делают — `tasker hooks uninstall` уберёт их заранее.
- **Сборка без встроенного фронтенда.** Свойство MSBuild `EmbedFrontend=false` (его ставят `--from-source` и `release.sh` при сборке демона) не встраивает `frontend/dist` в `Tasker.Web`: демону фронтенд не нужен.

### install.ps1 (Windows)

```powershell
.\install.ps1                      # релиз, с которым пришёл скрипт (рядом папка app\): в %LOCALAPPDATA%\Programs\Tasker
.\install.ps1 -From ФАЙЛ.zip|ПАПКА # из архива или папки с готовой сборкой
.\install.ps1 -Url АДРЕС.zip [-NoVerify]   # скачать; АДРЕС.zip.sha256 проверяется
.\install.ps1 -Prefix D:\Tools\Tasker -NoPath -NoCompletion -NoAutostart
.\install.ps1 -DryRun              # (то же -WhatIf) только показать, что будет сделано; в системе ничего не меняется
.\install.ps1 -Uninstall
```

Устанавливает самодостаточную сборку в `<Prefix>\app` (проверка дымовым тестом и подмена целиком, как на Unix), добавляет `<Prefix>\app` в **пользовательский** PATH (реестр `HKCU\Environment`, без прав администратора; имена вида `%USERPROFILE%` сохраняются; работающим окнам отправляется `WM_SETTINGCHANGE`), подключает автодополнение PowerShell (`tasker completion pwsh --install`) и включает автозапуск (`tasker mcp autostart enable` — задача Планировщика заданий для пользователя). Работающий демон перед заменой файлов останавливается (Windows блокирует запущенные программы) и после запускается снова: на Windows демон пока работает одним процессом, и обновление равно перезапуску (см. [«MCP-демон на Windows»](Windows)). Данные (`%LOCALAPPDATA%\Tasker`) установка, обновление и удаление не трогают. Скрипт — только ASCII и без синтаксиса новее PowerShell 5.1; проверяется тестами (`InstallPowerShellTests`) в PowerShell 7 на любой системе в режиме `-DryRun`, а настоящая установка (реестр, Планировщик, профиль) — на Windows по списку проверки в задаче TSK-120.

### Сборка релиза (`scripts/release.sh`)

```bash
scripts/release.sh                              # все платформы -> artifacts/release/<версия>/
scripts/release.sh --rid osx-arm64,win-x64      # выбранные (win-x64 win-arm64 linux-x64 linux-arm64 osx-arm64 osx-x64)
scripts/release.sh --no-r2r --out /tmp/rel      # без ReadyToRun (быстрее собирается, медленнее стартует)
```

Скрипт публикует `tasker` и `tasker-mcpd` (`dotnet publish -r <rid> --self-contained`, ReadyToRun) в одну папку `app/` на каждую платформу, добавляет `install.sh` (`install.ps1` для Windows) и `release.txt` (версия, платформа, коммит), упаковывает в `tasker-<версия>-<rid>.tar.gz` (Windows — `.zip`) и пишет `.sha256` рядом с архивом и общий `SHA256SUMS` (проверка: `shasum -a 256 -c SHA256SUMS`). Собрать можно с любой системы — пакеты среды выполнения нужной платформы .NET скачивает сам (нужна сеть при первой сборке); собранное для платформы этой машины скрипт запускает и сверяет версию. Единый файл (single-file) и обрезка (trimming) **не используются**: Autofac, EF Core, System.CommandLine и ASP.NET Core опираются на рефлексию (проверено: `PublishTrimmed` даёт около 110 предупреждений IL, и собранный `tasker` падает уже на `project create`), а единый файл дублировал бы среду выполнения в каждом из двух исполняемых файлов — общая папка вдвое меньше; размер каждого архива около 60 МБ. `tasker` и `tasker-mcpd` — две программы в одной папке; демон — один исполняемый файл с режимами (супервизор, рабочий процесс, `--single`).

**Версия.** Одно число для всех программ — файл `VERSION` в корне (`0.1.0`, `0.2.0-rc.1`); его читает `Directory.Build.props`, `tasker --version` печатает его же (сборка `install.sh --from-source` добавляет `+<коммит>`). Выпуск: правка `VERSION`, коммит, тег `v<версия>`, `scripts/release.sh` (если коммит помечен тегом `v*`, тег обязан совпасть с файлом). `--version X` задаёт номер вручную (пробная сборка).

### Пакетные менеджеры (будущее)

winget (Windows), Homebrew (macOS/Linux), пакеты apt/deb (и AUR) — отдельные задачи после этой: они будут брать готовые архивы релиза и их суммы SHA256.

## Требования

- .NET SDK 10
- Node.js 22+
