# Установка

На macOS Tasker ставится одним приложением `Tasker.app`: внутри него и консоль, и демон (см. [ниже](#macos-tasker.app)). На Linux и Windows Tasker ставится из архива релиза: в архиве две программы — консоль `tasker` (NativeAOT, около 18 МБ) и демон `tasker-mcpd` (один файл вместе с рантаймом .NET, около 127 МБ); на Windows рядом ещё `e_sqlite3.dll`. Ставить .NET не нужно, права администратора тоже; на Linux нужна системная `libicu` (см. [Платформы](Платформы)); SQLite встроена в консоль.

| Система | Архив | Установщик | Автозапуск демона |
|---|---|---|---|
| macOS (arm64, x64) | `Tasker-<версия>-osx-arm64.zip`, `-osx-x64.zip` | перенести `Tasker.app` в «Программы» | launchd (агент пользователя) |
| Linux (glibc 2.28+, x64, arm64) | `-linux-x64.tar.gz`, `-linux-arm64.tar.gz` | `install.sh` | systemd `--user` |
| Linux (любой, в том числе Alpine/musl) | `-linux-musl-x64.tar.gz`, `-linux-musl-arm64.tar.gz` (статические) | `install.sh` | systemd `--user` |
| Windows 10 1809+ (x64, arm64) | `-win-x64.zip`, `-win-arm64.zip` | `install.ps1` | Планировщик заданий |

Всего восемь архивов: шесть с `tasker` и `tasker-mcpd` и два с `Tasker.app`. Установщик проверяет, что архив подходит к системе (ОС и архитектура; на Linux с musl подскажет архив `linux-musl-*`). Подробнее о системах: [Платформы](Платформы).

## macOS: Tasker.app

Распакуйте архив своей архитектуры, перенесите `Tasker.app` в «Программы» и откройте. Подпись и нотаризация появятся позже, а пока macOS не пускает скачанное неподписанное приложение: один раз снимите с него карантин.

```bash
xattr -dr com.apple.quarantine /Applications/Tasker.app
```

При первом запуске:

- **Служба демона.** Приложение ставит агент launchd `com.technotronika.tasker.daemon` на `Tasker.app/Contents/Helpers/tasker-mcpd`. Он запускает демон при входе в систему и перезапускает после падения.
- **Команда `tasker`.** Приложение спрашивает, ставить ли команду. Это ссылка `~/.local/bin/tasker` на `Tasker.app/Contents/Helpers/tasker`, пароль не нужен. Если `~/.local/bin` нет в PATH, там же можно отметить добавление помеченного блока в `~/.zprofile` (для bash — в файл входа). Там же включается автодополнение по Tab. Отказались — приложение больше не спросит, команда останется в меню «Tasker → Установить команду tasker…».
- **Старая установка.** Если найдены служба `com.tasker.mcp`, `~/.local/share/tasker/app` или ссылка на них, приложение заменяет их сразу и сообщает об этом. Демон при этом перезапускается на несколько секунд. Настройки и данные не меняются. Вместо старых программ остаются ссылки на пакет, чтобы работали git-хуки со старым путём. Копия старых программ `app.previous` удаляется при следующем запуске. Не получилось — старая служба запускается снова, попытка повторится при следующем запуске.

Приложение, запущенное с образа диска или из случайного каталога Gatekeeper (`AppTranslocation`), ничего не подключает и просит перенести себя в «Программы»: иначе служба и ссылка вели бы на путь, которого скоро не будет. Сборки для разработки тоже ничего не подключают и не меняют чужой демон сами.

Что происходит дальше:

| Событие | Что будет |
|---|---|
| Новая версия заменила приложение на том же месте | консоль новая сразу. Работающий демон переходит на новую сборку без простоя при первом запуске приложения; пока оно не запущено, работает прежняя сборка, а после входа в систему запустится новая |
| Приложение перенесли в другую папку | команда не работает, пока приложение не открыто. Демон уходит сам через минуту. При запуске с нового места приложение чинит ссылку и службу и запускает демон оттуда |
| Приложение удалили | демон уходит сам через минуту, launchd не запускает его снова, пока файла программы нет. Вернули на то же место — демон запустится сам |
| «Tasker → Удалить команду и службу…» | остановка демона, удаление службы, ссылки, автодополнения и блока PATH. Данные и настройки остаются. Затем приложение закрывается, его можно перенести в Корзину |

Если приложение удалили без этого пункта, останутся ссылка и описание службы. Они ничего не делают, а убрать их можно так:

```bash
launchctl bootout gui/$(id -u)/com.technotronika.tasker.daemon
```

```bash
rm ~/Library/LaunchAgents/com.technotronika.tasker.daemon.plist ~/.local/bin/tasker
```

`tasker mcp autostart enable` из пакета управляет той же службой, что и приложение: метка одна. С образа диска и из `AppTranslocation` команда отказывается работать. Git-хуки, поставленные консолью из пакета, запоминают ссылку `~/.local/bin/tasker`, а не путь к пакету.

## Linux и Windows

```bash
install.sh --from tasker-0.1.0-linux-x64.tar.gz                                # из архива или каталога со сборкой
install.sh --url https://<адрес>/tasker-0.1.0-linux-x64.tar.gz                 # скачать; проверяется .sha256 рядом
```

```powershell
Expand-Archive tasker-0.1.0-win-x64.zip .; .\tasker-0.1.0-win-x64\install.ps1  # или: .\install.ps1 -From архив.zip
```

Повторный запуск — обновление, `--uninstall` / `-Uninstall` — удаление.

### install.sh (Linux)

На macOS `install.sh` отказывается ставить и отправляет к `Tasker.app`; там работает только `--uninstall`.

| Параметр | Что делает |
|---|---|
| `--from ПУТЬ` | архив `.tar.gz` или каталог с готовой сборкой |
| `--url АДРЕС` | скачать архив; `--no-verify` — без файла суммы |
| `--from-source` | собрать из исходников репозитория (`dotnet publish`, нужен .NET SDK 10 и C-компилятор платформы); `--no-daemon` — только консоль |
| `--prefix DIR` | другой каталог (по умолчанию `~/.local`) |
| `--add-to-path` | дописать `<prefix>/bin` в PATH профиля оболочки |
| `--no-autostart` | не включать автозапуск демона |
| `--no-completion` | не подключать автодополнение к оболочке |
| `--restart` | перезапустить работающий демон (иначе он переключается на новую сборку без простоя) |
| `--uninstall` | удалить |

### install.ps1 (Windows)

| Параметр | Что делает |
|---|---|
| `-From ПУТЬ`, `-Url АДРЕС` (`-NoVerify`) | архив `.zip` или папка со сборкой; скачивание с проверкой `.sha256` |
| `-Prefix ПАПКА` | другая папка (по умолчанию `%LOCALAPPDATA%\Programs\Tasker`) |
| `-NoPath`, `-NoCompletion`, `-NoAutostart` | не менять PATH, не подключать автодополнение, не включать автозапуск |
| `-DryRun` (`-WhatIf`) | только показать действия |
| `-Uninstall` | удалить |

## Что ставится куда

| Что | macOS | Linux | Windows |
|---|---|---|---|
| Программы | `Tasker.app/Contents/Helpers/` | `<prefix>/share/tasker/app/` | `<Prefix>\app\` |
| Команда | `~/.local/bin/tasker` (ссылка) | `<prefix>/bin/tasker` (ссылка) | `<Prefix>\app` в пользовательском PATH |
| Скрипты автодополнения | `~/.local/share/tasker/completions/` | `<prefix>/share/tasker/completions/` | `tasker completion pwsh --install` |
| Данные, настройки, логи | `~/Library/Application Support/Tasker` | `~/.local/share/Tasker` | `%LOCALAPPDATA%\Tasker` |

На Linux и Windows установка заменяется целиком, а путь к программе не меняется, поэтому автозапуск и git-хуки переживают обновление.

- **Автозапуск.** Если он не включён, установщик выполняет `tasker mcp autostart enable` (демон сразу стартует); не вышло (например, нет systemd) — будет предупреждение. Подробнее: [Демон MCP](Демон-MCP).
- **Автодополнение.** В файл оболочки добавляется один помеченный блок; подробнее: [Консоль](Консоль#автодополнение-по-tab).
- **PATH.** Если `<prefix>/bin` не в PATH, скрипт печатает строку для профиля; `--add-to-path` дописывает её сам.

## Обновление и удаление на Linux и Windows

Обновление — повторный запуск установщика новой версии (`install.sh --from <архив>`): каталог `app/` заменяется целиком, путь к программе
тот же. Работающий демон `install.sh` переводит на новую сборку без простоя (`tasker mcp upgrade`); `install.ps1` останавливает его на
время замены файлов (Windows не даёт заменить работающую программу) и запускает снова.

Удаление выключает автозапуск, останавливает демон и убирает программу, ссылку, скрипты автодополнения и свой блок в файле оболочки. Данные и рабочие папки с `.tasker` не трогаются; git-хуки остаются и без `tasker` ничего не делают (`tasker hooks uninstall` уберёт их заранее).
