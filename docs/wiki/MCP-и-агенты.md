# MCP и агенты

Tasker даёт ИИ-агентам MCP-сервер (Streamable HTTP, без состояния): агент работает с задачами теми же инструментами, что человек в интерфейсе, с теми же проверками прав, версиями и изоляцией проектов.

## Подключение

| Где | Адрес | Аутентификация |
|---|---|---|
| Демон или десктоп (локально) | `http://127.0.0.1:5719/mcp` (порт: `tasker mcp port`) | токен не нужен; агента выбирает заголовок `X-Tasker-Agent: <id агента>`, без него вызов идёт от локального агента `agent` области |
| Сервер | `http(s)://<сервер>/mcp` | `Authorization: Bearer tsk_…` |

```bash
claude mcp add --transport http tasker http://127.0.0.1:5719/mcp
claude mcp add --transport http tasker http://127.0.0.1:5719/mcp --header "X-Tasker-Agent: <id агента>"
```

Готовая команда подключения есть в настройках пользователя, вкладка «Агенты». Локальный адрес слушает только `127.0.0.1`. Как запустить демон — [Демон-MCP](Демон-MCP); десктоп отдаёт MCP сам, пока демон не запущен ([Интерфейс](Интерфейс)).

## Агенты и права

- Агент — пользователь с типом `agent`: участвует в проектах и подчиняется тем же правам, но без почты и пароля, не бывает админом и не управляет пользователями, агентами, токенами и участниками.
- Токен агента принимает только MCP, JWT людей в MCP не принимается.
- На сервере агентов создают люди (`POST /api/agents`), токены — `POST /api/agents/{id}/tokens`: значение `tsk_…` показывается один раз, токенов может быть несколько, срок действия необязателен, отзыв — `DELETE /api/agents/{id}/tokens/{tokenId}`. Доступ к проектам — участником проекта ([Настройка-и-сервер](Настройка-и-сервер)).
- В локальном режиме у каждой области свои пользователи: id из `X-Tasker-Agent` проверяется в выбранной области (в чужой — `[forbidden]`).

## Область и проект

| Аргумент | Что значит | Если не передан |
|---|---|---|
| `workspace` (любой инструмент) | имя папки из `list_workspaces` (повторы: `name`, `name-2`) или её путь | одна область — берётся она; несколько — `[invalid] workspace is required: …`; областей нет — `[invalid]` с подсказкой |
| `projectId` | id проекта | в области (на сервере — среди проектов агента) один проект — берётся он; иначе `[invalid] projectId is required` |

- На сервере область одна, аргумента `workspace` нет.
- Разрешены только области демона или открытые вкладки десктопа; неразрешённая и несуществующая одинаково дают `[not_found]`.
- Разрешённая область, которая ещё открывается, ждётся до 5 с (`TASKER_MCP_OPEN_WAIT_MS`), затем `[unavailable]` (повторить через пару секунд); не открылась (папку удалили, диск не подключён) — `[failed]` с причиной, демон пробует снова раз в 30 с.
- `list_workspaces` возвращает `name`, `path`, `status` (`open`, `opening`, `failed`), `projects`, `error`.

## Инструменты

Всего 62 инструмента; все, кроме `list_workspaces`, принимают `workspace` (в серверном режиме его нет), проектные — ещё и `projectId`.

| Группа | Инструменты | Для чего |
|---|---|---|
| Области и проекты | `list_workspaces`, `whoami`, `list_projects`, `get_project`, `create_project`, `update_project`, `list_users`, `list_project_members`, `list_workspace_problems` | обзор, проекты, участники; `list_workspace_problems` — нечитаемые файлы `.tasker` |
| Задачи | `list_tasks`, `get_task`, `create_task`, `update_task`, `delete_task` | работа с задачами; значения полей — параметр `fields` |
| Типы, статусы, наборы | `list_/create_/update_/delete_` + `task_type(s)`, `status(es)`, `status_set(s)` | схема процесса |
| Поля | `list_/get_/create_/update_/delete_` + `field(s)`, `enum(s)` | поля и перечисления ([Связи-и-поля](Связи-и-поля)) |
| Связи | `list_link_types`, `create_link_type`, `update_link_type`, `delete_link_type`, `get_task_links`, `link_tasks`, `unlink_tasks` | типы связей и связи задач |
| Доски | `list_boards`, `get_board`, `create_board`, `update_board`, `delete_board`, `move_task` | доски с задачами по колонкам; `move_task` двигает задачу |
| Серии | `list_series`, `get_series`, `create_series`, `update_series`, `delete_series`, `series_health`, `add_task_to_series`, `remove_task_from_series`, `renumber_task`, `find_tasks_by_reference` | серии, номера, поиск задачи по ссылке ([Концепции](Концепции)) |
| Блокировки | `lock_entity`, `unlock_entity`, `get_lock` | занять сущность на время серии правок |

`list_tasks` фильтрует по `typeIds`, `statusIds`, `seriesIds` (ИЛИ внутри параметра, И между ними) и по полям: `field: ["Имя=значение"]`. Инструменты помечены «только чтение» или «разрушительные» — клиент по этому решает, спрашивать ли подтверждение.

### Краткие списки

Инструменты со списками задач (`list_tasks`, `get_board`, `find_tasks_by_reference`) отдают превью описания: `descriptionLength` (по умолчанию 200) — сколько символов вернуть; `0` — без описания, `-1` — целиком. В записи также `descriptionTruncated`, длина полного описания, `linksCount`, `parentIds`, `childCount` (больше 0 — эпик). Список всегда плоский, иерархия в `parentIds` и `childCount`. Полное описание — `get_task`.

## Ошибки, версии, блокировки

Ошибка — результат с `isError: true`, текст начинается с кода.

| Код | Когда |
|---|---|
| `[invalid]` | неверные аргументы; не указаны `workspace` или `projectId` |
| `[forbidden]` | нет прав; неизвестный агент в `X-Tasker-Agent` |
| `[not_found]` | нет сущности, проекта или разрешённой области |
| `[in_use]` | удаляемая сущность используется |
| `[modified]` | устаревший `version` |
| `[locked]` | сущность занята другим; в тексте имя владельца |
| `[unavailable]` | область открывается: повторить |
| `[failed]` | область не открылась (локальный режим) |

- `update_*` и `delete_*` требуют `version`: сначала `get_*`, затем правка. `[modified]` — перечитать и повторить.
- Одиночным правкам блокировка не нужна. Для серии связанных вызовов: `lock_entity` (сущности `project`, `task`, `taskType`, `linkType`, `field`, `enum`, `status`, `statusSet`, `board`, `series`), повторный вызов продлевает; блокировка сама истекает через 2 минуты; `unlock_entity` снимает.

Ограничения: агент не входит в REST-API; MCP без токена доступен только с этой машины.
