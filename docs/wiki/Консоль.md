# Консоль

`tasker` работает с рабочей областью (папкой `<папка>/.tasker`) напрямую. Приложение и демон запускать не нужно, но они не мешают; вызов занимает 10–15 мс. Параметры — `tasker <группа> --help`.

## Общие параметры

Можно ставить в любое место команды.

| Параметр | Что делает |
|---|---|
| `-w, --workspace <папка>` | рабочая область (по умолчанию текущая папка) |
| `--sqlite <файл>` | файл SQLite вместо папки: та же база, что открывают десктоп и сервер, с ней можно работать одновременно. Файла нет — он создаётся. У такой области нет кэша и файлов: `sync` и `migrate` сообщают, что делать нечего |
| `-p, --project <id или имя>` | проект; по умолчанию `TASKER_PROJECT`, иначе единственный проект области (при нескольких — ошибка с подсказкой) |
| `--json` | результат в JSON, как в API |
| `-q, --quiet` | без первой строки `Found N`; `sync` молчит, если всё в порядке |
| `--no-wrap`, `--truncate` | обрезать длинные строки списков по ширине окна (в терминале по умолчанию) |
| `--no-truncate` | не обрезать никогда (при перенаправлении вывода — по умолчанию) |
| `--width N` | ширина для обрезки (от 20); `0` или `auto` — ширина терминала; по умолчанию `TASKER_WIDTH` |
| `-i, --interactive` | интерактивный режим: меню в терминале вместо команды (см. ниже) |

Сущности указываются по id или имени; вместо id годится короткий (8 символов, первая колонка списков). Задачи — по ссылке (`TSK-5`) или id. Ошибка — сообщение в stderr и код 1.

## Команды

Для каждой сущности есть `create`, `list`, `get`, `update`, `delete` (если не сказано иное): `update` меняет только указанное, `get --json` печатает запись как в API. `project delete` показывает сводку и спрашивает подтверждение (`--yes` — без вопроса).

| Команда | Что делает |
|---|---|
| `project` | проекты |
| `status create <имя> [--color #RRGGBB] [-d описание]` | статусы проекта |
| `status-set create <имя> --status <статус>...` | наборы статусов: порядок состояний |
| `task-type create <имя> --status-set <набор> [--field Имя[:required]]...` | типы задач; в `update` поля меняют `--field`, `--add-field`, `--remove-field` (значения у задач: `--drop-values` или `--keep-values`) |
| `link-type create <имя> --outward <название> [--inward <название>] [--allow-cycles true\|false] [--hierarchical true\|false]` | типы связей |
| `field create <имя> --type <тип> [--multiple] [--enum <перечисление>]` | поля проекта |
| `enum create <имя> --value <значение>...` | перечисления; в `update`: `--add-value`, `--remove-value`, `--rename-value`, `--values` |
| `series create <имя> --prefix TSK` | серии с номерами `TSK-N`; ещё `add-task`, `remove-task`, `renumber-task` |
| `task create <заголовок> --type <тип> [--status] [-d] [--series] [--parent] [--field Имя=значение]... [--custom-field Имя:тип]...` | задачи |
| `task link <задача> <связь> <другая>`, `task unlink …`, `task links <задача>` | связи, например `task link TSK-1 includes TSK-2` |
| `board create <имя> --status-set <набор> --column "Имя=статус,статус"... [--column-filter "Колонка:Поле>=3"]...` | доски |
| `board show <доска>` | вся доска; `--limit N` — задач на колонку, `--all` |
| `board tasks <доска> <колонка>` | задачи колонки, как `task list` |
| `user`, `agent` | пользователи и агенты (только имена) |
| `lock acquire\|release\|show <вид> <сущность>` | блокировка на время правки (истекает через 2 минуты) |
| `whoami [<имя>]` | ваше имя в блокировках |
| `mcp start\|stop\|restart\|status\|run\|upgrade` | демон MCP ([Демон MCP](Демон-MCP)) |
| `mcp autostart enable\|disable\|status` | автозапуск демона при входе |
| `mcp workspace add\|remove\|list`, `mcp config`, `mcp port [<порт>]` | глобальные настройки MCP |
| `sync [--quiet]` | сверить кэш с файлами |
| `cleanup [--resolve-conflicts] [--dry-run] [--check]` | убрать битые ссылки и слить вторые папки проектов после слияния git |
| `migrate [--dry-run] [--check]` | привести файлы к текущей версии формата, назвать файлы и папки проектов по именам |
| `hooks install\|uninstall\|status` | git-хуки |
| `manual [<тема или слово>]` (`howto`) | справочник рецептов |
| `completion zsh\|bash\|pwsh` | скрипт автодополнения |

Сущности: [Концепции](Концепции), [Связи и поля](Связи-и-поля).

## Список и поиск задач

```bash
tasker task list --status Бэклог "В работе" --type Баг   # ИЛИ внутри параметра, И между параметрами
tasker task list --field "Оценка>=3" --sort -Оценка      # условие в кавычках
tasker task list --limit 20 --offset 20 --flat
```

| Параметр | Значение |
|---|---|
| `--status`, `--type`, `--series` | несколько значений: `--status A --status B` или `--status A B` |
| `--field` | `Имя=значение`, `Имя!=значение`, `Имя>=значение` (`>`, `<`, `<=` для чисел и дат), `Имя:set`, `Имя:unset`, `Имя:attached`, `Имя:detached`; несколько условий — все сразу |
| `--sort` | ключи через запятую, `-` — по убыванию: `status`, `type`, `title`, `created`, `updated`, `series` или имя поля; задачи без значения — в конце; по умолчанию порядок создания |
| `--offset`, `--limit` | страница (по умолчанию 0 и 50, лимит 1–200) |
| `--all` | всё без страниц (несовместимо с `--offset/--limit`) |
| `--flat` | плоский список; по умолчанию дети эпика идут под ним с отступом |
| `--description-length N` | только с `--json`: сколько символов описания (`0` — нет, `-1` — всё) |

Первая строка текстового списка — число найденного: `Found 3` или `Found 106, shown 1-50 (use --offset/--limit)`.

## Интерактивный режим `tasker -i`

`tasker -i` (без команды) открывает в терминале сессию с меню: выбрали действие — прошли шаги — вернулись в меню, как в `git add -i`. Область — текущая папка, `-w` или `--sqlite`; проект — `-p`, `TASKER_PROJECT` или единственный в области, при нескольких проектах первым шагом идёт его выбор (сменить можно пунктом «Switch project»). Работает только в терминале: если ввод или вывод перенаправлены — ошибка и код 1; `-i` вместе с командой — ошибка.

| Пункт меню | Что делает |
|---|---|
| Create | создать проект, задачу, статус, набор статусов, тип задачи, серию, поле, перечисление, доску, тип связи, пользователя или агента |
| Change | изменить те же сущности; у задачи — заголовок, описание, тип, статус, серии, родители, значения полей, связи; у остальных — имя и основные параметры (цвет, статусы набора, набор статусов и поля типа, названия сторон и флаги типа связи, тип/число значений/перечисление поля, значения перечисления, наборы и колонки доски, префикс серии) |
| Delete | удалить те же сущности, с подтверждением; `project` показывает ту же сводку, что `project delete` |
| Switch project | выбрать другой проект области |
| Quit | выход (`q` или Ctrl+C в меню; Ctrl+C — отовсюду) |

Шаги:

- выбор из списка — стрелками, Enter; набранный текст фильтрует список (сущности, статусы, типы, значения перечислений); где значений несколько (статусы набора, серии, родители) — отметка пробелом, порядок отметки сохраняется;
- текст — строка ввода с проверкой: обязательные значения, числа, даты `yyyy-MM-dd`, цвет `#RRGGBB`, префикс серии; ошибка показывается под полем;
- многострочный текст (описание, значения перечисления, колонки доски) — `e` открывает `$VISUAL`/`$EDITOR` (иначе `vi`, на Windows `notepad`), Enter принимает как есть;
- там, где команда требует решения о каскаде (значения отвязанного поля типа, удаляемое значение перечисления, несколько значений при переходе поля к одному), — тот же выбор отдельным шагом;
- Esc — шаг назад с сохранением введённого (в первом шаге — назад в меню, без изменений).

Действие выполняется той же командой консоли, что и из строки (`tasker status create …`, `task update …`), с `--expected-version` версии, показанной при выборе: результат — её вывод, текст ошибки — её текст. Конфликт версии или блокировка правки (`Modified by someone else:`, `Locked:`) — экран «Conflict», `r` повторяет с текущими данными; другая ошибка — экран «Error», Enter возвращает к последнему шагу, чтобы поправить.

## Справочник `tasker manual`

Короткие рецепты с готовыми командами: `tasker manual` — список тем, `tasker manual <тема>` — рецепт, `tasker manual <слово>` — поиск. Язык — `--lang` или `TASKER_LANG`.

## Автодополнение по Tab

Подсказываются команды, параметры и значения из текущей области: проекты, статусы, типы, серии, поля, перечисления, колонки досок, ссылки задач (`TSK-7<Tab>`). Поддержаны zsh, bash и PowerShell; cmd.exe — нет.

- macOS и Linux: `scripts/install.sh` кладёт скрипты в `<prefix>/share/tasker/completions/` и дописывает один помеченный блок в `~/.zshrc` или файл bash (копия — `.tasker-backup`); `--no-completion` отключает.
- Вручную: `eval "$(tasker completion bash)"` или `source <(tasker completion zsh)`.
- PowerShell: `tasker completion pwsh --install` (блок в профилях), `--uninstall` — убрать.

## sync, cleanup, migrate и хуки

Файлы `.tasker` — источник правды, кэш пересобираемый; десктоп и демон сами подхватывают `git pull`, `tasker` сверяет кэш при старте.

| Команда | Что делает |
|---|---|
| `tasker sync` | сверить кэш сейчас (через демон, если он обслуживает папку: `via daemon`, иначе `via direct`); показывает нечитаемые файлы (конфликт git, битый YAML) |
| `tasker cleanup` | слить вторую папку проекта (после слияния веток, где проект переименовали) в папку с текущим именем; убрать ссылки на отсутствующие серии, связи с отсутствующими задачами и типами; циклы только показывает. `--resolve-conflicts` перенумеровывает повторы (раньше созданная задача сохраняет номер), `--dry-run` ничего не пишет, `--check` — код 2, если что-то нужно менять |
| `tasker migrate` | привести файлы к текущей версии формата и назвать файлы и папки проектов по именам; `--dry-run`, `--check` (код 2) |
| `tasker hooks install` | хуки `post-merge`, `post-checkout`, `post-rewrite` запускают `tasker sync --quiet` |

Хуки добавляют свой помеченный блок, чужие команды не трогают и git не прерывают. Ограничение: хуки локальные, их ставят в каждом клоне; после `git reset --hard`, `git stash pop` и слияния с конфликтом хуков нет, нужен `tasker sync`. См. [Хранение и git](Хранение-и-git).

Особенности Windows (кодировка, длина пути, переводы строк): [Платформы](Платформы#windows).
