# Разработка

Консоль `tasker` и демон `tasker-mcpd` написаны на Rust (`rust/`): для них нужен только стабильный toolchain Rust 1.85+ с `cargo` (`rustup` или `brew install rust`). Десктоп, сервер, фронтенд и .NET-тесты — на .NET: для них нужны .NET SDK 10 и Node.js с npm; остальное тянется через cargo, NuGet и npm.

## Структура

| Папка | Что там |
|---|---|
| `frontend/` | React + TypeScript (Vite), единственный фронтенд |
| `src/Tasker.Core` | домен и сервисы |
| `src/Tasker.Configs` | настройки из переменных окружения и аргументов |
| `src/Tasker.Storage.Files`, `src/Tasker.Storage.Db` | хранение файлами (`.tasker`) и в БД (EF Core: SQLite, Postgres) |
| `src/Tasker.Mcp` | инструменты MCP поверх сервисов Core |
| `src/Tasker.Web` | API и встроенный фронтенд (`frontend/dist` как ресурс) |
| `src/Tasker.Server`, `src/Tasker.Desktop` | хосты: ASP.NET Core и Avalonia (Web in-process на 127.0.0.1) |
| `rust/` | консоль `tasker` и демон `tasker-mcpd` (Cargo workspace, крейты в `rust/crates/`, см. `rust/README.md`); `rust/tests/golden` — эталоны поведения |
| `src/Tasker.Global`, `src/Tasker.Daemon` | глобальные настройки; клиент демона для десктопа |
| `src/Tasker.Cli`, `src/Tasker.Daemon.Host` | прежняя .NET-версия консоли и демона: эталон для сверки, в релиз не входит, будет удалена (TSK-143) |
| `tests/Tasker.Tests` | тесты xUnit |
| `tools/Tasker.Stress` | стенд параллельной работы |
| `scripts/` | установка, релиз, тесты в Docker |

## Сборка и запуск

Консоль и демон:

```bash
cd rust && cargo build --release      # rust/target/release/tasker и tasker-mcpd
scripts/install.sh --from-source      # собрать и установить в ~/.local (как релиз)
```

Десктоп и сервер: фронтенд встраивается при сборке .NET, поэтому сначала он:

```bash
cd frontend && npm install && npm run build
dotnet build
```

| Что | Команда |
|---|---|
| Сервер (:5156, SQLite в памяти) | `dotnet run --project src/Tasker.Server` |
| Сервер с файлом SQLite | `dotnet run --project src/Tasker.Server -- --sqlite=tasker.db` |
| Десктоп | `dotnet run --project src/Tasker.Desktop` (`-- --files=<папка>` откроет вкладку сразу) |
| Фронтенд с hot reload | сервер, затем `cd frontend && npm run dev` (Vite на :5173, `/api` идёт на :5156) |
| Десктоп с Vite | `TASKER_FRONTEND_DEV_URL=http://localhost:5173 dotnet run --project src/Tasker.Desktop` (Vite проксирует `/w/<папка>/api` и `/mcp` на порт 5719) |

Боевые настройки сервера (Postgres, ключ подписи): [Настройка и сервер](Настройка-и-сервер). Линтер фронтенда: `npm run lint`. Сборка без встраивания фронтенда (тесты): `-p:EmbedFrontend=false`.

## Тесты

Rust (консоль и демон):

```bash
cd rust && cargo test                                # или cargo nextest run (так в CI, профиль ci в rust/.config/nextest.toml)
cd rust && cargo clippy --all-targets -- -D warnings
cd rust && cargo fmt                                 # rustfmt.toml: max_width = 140
```

.NET (десктоп, сервер, домен на C# и сквозные сценарии консоли и демона):

```bash
dotnet test                                                             # все
dotnet test tests/Tasker.Tests --filter "FullyQualifiedName~CliTests"   # по фильтру
scripts/test-linux.sh [--filter "..."]    # на Linux в Docker (нужен docker)
scripts/test-linux.sh --stress "upgrade"  # стенд вместо тестов
```

- Тесты сквозные: настоящее хранилище (файлы и SQLite), процессы `tasker`, демон на свободном порту с отдельным `TASKER_HOME`.
- Идут параллельно: окружение переопределяется через `AppEnvironment.Override`; менять переменные окружения и текущую папку всего процесса в тестах нельзя.
- Тест под конкретную ОС помечается `[PlatformFact(TestPlatform.Windows)]`: на других системах он считается пропущенным.

### Против внешнего бинарника

Процессные тесты (`TaskerProcess`, `TestWorkspace.Create(…, asProcess: true)`, `DaemonFixture`) по умолчанию запускают `dotnet tasker.dll` из каталога тестов. Переменная `TASKER_BIN` подменяет консоль на любой исполняемый файл — так те же сценарии проверяют Rust-сборку: `tasker-mcpd` консоль ищет рядом с собой, поэтому он должен лежать в том же каталоге; `TASKER_MCPD_BIN` нужна только тестам, которые запускают демон сами (`TaskerProcess.DaemonCommand`), по умолчанию это сосед `TASKER_BIN`.

```bash
scripts/perf/publish.sh /tmp/tasker-bin        # Rust: cargo build --release, tasker и tasker-mcpd в один каталог
TASKER_BIN=/tmp/tasker-bin/tasker TASKER_MCPD_BIN=/tmp/tasker-bin/tasker-mcpd dotnet test tests/Tasker.Tests --filter "Binary!=in-process"
```

Тесты, которые гоняют консоль внутри процесса тестов (`CliApp.Run` через `TestWorkspace.Run`/`Invoke`), чужой бинарник не проверяют и помечены трейтом `[InProcess]` (`Binary=in-process`): класс целиком, если он весь о консоли и без процессных тестов, иначе — отдельные методы. Фильтр выше их пропускает; без переменной и фильтра прогон прежний. Новые сквозные сценарии консоли лучше писать через `asProcess: true` или `RunProcess` — они работают в обоих режимах. Переменные читаются один раз при загрузке сборки тестов и дочерним процессам не передаются (`TestRun`).

Стенд параллельной работы (временная папка, свой демон; данные и демон на 5719 не трогает; код возврата 1 при нарушении инвариантов):

```bash
dotnet run -c Release --project tools/Tasker.Stress -- --clients 10 --client mix --scenarios create,locks
```

## Golden-корпус и сверка с .NET

`rust/tests/golden/` — эталоны поведения .NET-сборки, которые Rust-версия повторяет буквально: каноническая область `.tasker` со всеми
сущностями и «опасными» строками, версии файлов, стиль YAML, вывод команд консоли, результат `migrate`, снапшоты MCP (подробности —
`rust/tests/golden/README.md`). `cargo test` сверяет с ним Rust-сборку.

```bash
scripts/golden/generate.py                                  # переснять корпус .NET-сборкой (собирается из репозитория)
scripts/golden/generate.py --verify --diff --bin <каталог>  # сверить сборку (tasker и tasker-mcpd в каталоге) с корпусом
scripts/completion-diff.py --net <tasker .NET> --rs <tasker Rust>   # автодополнение [suggest] байт в байт
python3 -I scripts/test-mixed-upgrade.py <tasker-mcpd .NET> rust/target/release/tasker-mcpd rust/tests/golden/workspace 3
                                                            # .NET-супервизор <-> Rust-рабочий процесс под нагрузкой
```

Расхождение с корпусом — либо ошибка переноса, либо баг .NET, который заводится задачей. Корпус переснимается, когда меняется вывод
консоли, схема инструментов MCP или формат файлов; дифф и есть список изменений поведения.

## Устройство

- DI: Autofac. `TaskerWebApp.CreateBuilder<THostModule>()` подключает `CoreModule` и `WebModule`, хост добавляет `ServerModule` или `DesktopModule`.
- Логи: Serilog, настраивается в `Program` хоста. Сервер пишет в консоль; десктоп ещё и в `logs/tasker-*.log` каталога данных (файл на час, хранятся 23 часа).

| Добавить | Шаги |
|---|---|
| Команду консоли | узел в дереве `rust/crates/tasker-cli/src/spec.rs`, обработчик в `rust/crates/tasker-cli/src/commands/` |
| Инструмент MCP | Rust: описание в `rust/crates/tasker-mcp/src/tools.json` и обработчик в `rust/crates/tasker-mcp/src/tools/`; десктоп (.NET): метод с `[McpServerTool]` в `src/Tasker.Mcp/Tools` |
| Страницу интерфейса | компонент в `frontend/src/pages`, маршрут в `frontend/src/App.tsx` |

## Сборка релиза

```bash
scripts/release.sh                                   # все платформы, которые собираются на этой машине -> artifacts/release/<версия>/
scripts/release.sh --rid osx-arm64,linux-arm64       # выбранные; --rid all — все восемь или ошибка до сборки
scripts/release.sh --rid linux-x64 --builder docker  # Linux с любой машины: cargo | zigbuild | docker
```

Скрипт собирает `tasker` и `tasker-mcpd` через `cargo build --release` (профиль из `rust/Cargo.toml`: LTO, `opt-level = "s"`, `strip`)
для восьми RID — `osx-arm64`, `osx-x64`, `linux-x64`, `linux-arm64`, `linux-musl-x64`, `linux-musl-arm64`, `win-x64`, `win-arm64`;
macOS и Windows — на своей ОС, Linux — `cargo zigbuild` (glibc не новее `--glibc`, по умолчанию 2.28) или в Docker. Архив
`tasker-<версия>-<rid>.tar.gz` (Windows — `.zip`): `app/` с двумя программами, установщик и `release.txt`; рядом `.sha256` и общий
`SHA256SUMS` (`shasum -a 256 -c SHA256SUMS`). Все платформы сразу — workflow `.github/workflows/release-build.yml` (fmt, clippy и
nextest на Linux, macOS и Windows, архивы — артефакты прогона; релизов и тегов он не создаёт).

Версия одна на все программы — файл `VERSION` в корне (`build.rs` крейта `tasker-version`); `tasker --version` печатает её, у сборки из
исходников — с коммитом (`0.1.0+f2a114d`). Выпуск: правка `VERSION`, коммит, тег `v<версия>`, `scripts/release.sh` (тег должен
совпадать с файлом).

Сценарий обновления у пользователя (.NET-установка с работающим демоном → `install.sh` нового архива → без единого отказа →
`tasker mcp restart`):

```bash
scripts/test-upgrade-from-dotnet.sh <.NET-архив> <Rust-архив>       # на этой машине (launchd/systemd), всё изолировано
scripts/test-linux-systemd.sh --archive <tasker-…-linux-arm64.tar.gz>  # Linux под настоящим systemd --user в Docker
```
