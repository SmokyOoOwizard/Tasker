# Разработка

## Структура репозитория

```
frontend/              React + TypeScript (Vite) — единственный фронтенд
src/Tasker.Configs/    настройки из переменных окружения и аргументов
src/Tasker.Core/       общая бизнес-логика (домен, сервисы)
src/Tasker.Storage.Db/     хранение задач в БД: EF Core, SQLite (файл или в памяти) или Postgres
src/Tasker.Storage.Files/  хранение задач файлами в <папка>/.tasker (для версионирования в git)
src/Tasker.Mcp/        MCP-сервер для агентов (/mcp): инструменты поверх сервисов Core
src/Tasker.Web/        общий веб-слой: API-эндпоинты + встроенный фронт (frontend/dist как ресурс)
src/Tasker.Server/     хост ASP.NET Core для сервера (режим Server)
src/Tasker.Cli/        консольная команда tasker (System.CommandLine): работает с хранилищем напрямую; управляет демоном MCP
src/Tasker.Global/     глобальные настройки (settings.json) и каталоги данных Tasker — общие у десктопа, консоли и демона
src/Tasker.Daemon/     клиентская часть демона MCP (без веб-слоя): файлы состояния, управление (start/stop/status), службы автозапуска (launchd, systemd, Планировщик заданий Windows), отчёты о сериях
src/Tasker.Daemon.Host/ сам демон MCP — отдельная программа tasker-mcpd (ASP.NET Core): хост MCP для рабочих областей из настроек
tools/Tasker.Stress/   стенд параллельной работы (см. «Параллельная работа»)
src/Tasker.Desktop/    Avalonia-приложение: поднимает Tasker.Web in-process на 127.0.0.1
                       со случайным портом (режим Local) и открывает его в NativeWebView
```

## DI и логирование

- **Autofac.** `TaskerWebApp.CreateBuilder<THostModule>()` подключает общие модули `CoreModule` и `WebModule`, а хост добавляет свой: `ServerModule` или `DesktopModule`.
- **Serilog.** `Log.Logger` настраивается в `Program` каждого хоста. Сервер пишет в консоль. Десктоп пишет в консоль и в `~/Library/Application Support/Tasker/logs` (`%LOCALAPPDATA%\Tasker\logs` на Windows): новый файл каждый час, файлы старше 23 часов удаляются.

## Тесты

```bash
dotnet test
```

`tests/Tasker.Tests` (xUnit): сквозные проверки команды `tasker` на настоящем хранилище — и папке с файлами, и SQLite, — общий код рабочих областей (канонический путь) и блокировки, в том числе с настоящими параллельными процессами `tasker`. Тесты идут параллельно (xUnit): окружение у каждого своё — `TASKER_HOME`, `TASKER_PROJECT` и `TASKER_SERVICE_*` переопределяются только для теста через `AppEnvironment.Override` и передаются дочерним процессам, а текущая папка задаётся запуском отдельного процесса `tasker`; менять переменные окружения и текущую папку всего процесса в тестах нельзя. Для проверки чужой блокировки нужен `python3`. Тесты хуков работают на настоящем git. Тест, которому нужна определённая система, помечается `[PlatformFact(TestPlatform.Windows)]` (`PlatformFactAttribute`): на других системах он явно пропускается (`skipped`), а не молча проходит; правила Windows (имена файлов, CRLF, пути) — чистые функции и проверяются везде. Тесты демона запускают настоящие процессы `tasker` с отдельным каталогом данных (`TASKER_HOME`) и свободным портом; launchctl и systemctl в тестах подменены — настоящую службу тесты не трогают.

## Сборка

Фронт встраивается в `Tasker.Web` при сборке .NET, поэтому сначала собирается он:

```bash
cd frontend && npm install && npm run build
dotnet build
```

## Запуск

Сервер (http://localhost:5156). Без настроек — SQLite в памяти и временный ключ подписи:

```bash
dotnet run --project src/Tasker.Server
```

Сервер с файлом SQLite:

```bash
dotnet run --project src/Tasker.Server -- --sqlite=tasker.db
```

В продакшене — Postgres и постоянный ключ подписи:

```bash
TASKER_DB_CONFIGS_POSTGRES_CONNECTION_STRING='Host=...;Database=tasker;Username=...;Password=...' TASKER_AUTH_CONFIGS_SIGNING_KEY='<секрет от 32 символов>' dotnet Tasker.Server.dll
```

Десктоп (пустое окно — папку выбрать в нём):

```bash
dotnet run --project src/Tasker.Desktop
```

Десктоп сразу с вкладкой папки:

```bash
dotnet run --project src/Tasker.Desktop -- --files=/path/to/workspace
```

## Разработка фронта с hot reload

```bash
dotnet run --project src/Tasker.Server   # API на :5156
cd frontend && npm run dev               # Vite на :5173, /api проксируется на :5156
```

Чтобы десктоп показывал Vite dev-сервер вместо встроенной сборки:

```bash
TASKER_FRONTEND_DEV_URL=http://localhost:5173 dotnet run --project src/Tasker.Desktop
```

Vite проксирует `/w/<папка>/api` и `/mcp` на постоянный порт десктопа (`5719`).
