# Платформы

Tasker работает на macOS, Linux и Windows; формат файлов `.tasker` на всех системах одинаков, поэтому репозиторий можно вести с любой из них. Установка: [Установка](Установка).

## Поддержка

| | macOS | Linux | Windows |
|---|---|---|---|
| Статус | проверен | проверен (в Docker, включая настоящий `systemd --user`) | экспериментально: код написан и собирается, на самой Windows не проверялся |
| Минимум | Apple Silicon и Intel | glibc (Debian, Ubuntu, Fedora, Arch…), x64 и arm64, библиотека ICU; Alpine (musl) не поддерживается | Windows 10 1809+, PowerShell 5.1 или 7, x64 и arm64 |
| Установщик | `install.sh` | `install.sh` | `install.ps1` |
| Автозапуск демона | launchd, `~/Library/LaunchAgents/com.tasker.mcp.plist` | `systemd --user`, `~/.config/systemd/user/tasker-mcp.service` | Планировщик заданий, задача «Tasker MCP» текущего пользователя |
| Фоновый запуск | отдельный сеанс процесса (`setsid`) | то же | процесс без окна, не привязанный к консоли и Ctrl+C |
| Каталог данных | `~/Library/Application Support/Tasker` | `~/.local/share/Tasker` | `%LOCALAPPDATA%\Tasker` |
| Бесшовное обновление демона | да | да | выключено по умолчанию |
| Права администратора, .NET | не нужны | не нужны | не нужны |

Автозапуск включается командой `tasker mcp autostart enable`, выключается `disable`, состояние показывает `status`; остальное про демон: [Демон MCP](Демон-MCP).

## Linux

- Служба `systemd --user` стартует при входе пользователя. Чтобы демон поднимался после перезагрузки без входа, выполните `loginctl enable-linger $USER`.
- Служба перезапускается при падении через 5 секунд.
- Без пользовательского сеанса systemd (`sudo -u`, `su`, часть SSH-сеансов) `autostart enable` сообщает причину и ничего не оставляет; на системах без systemd автозапуск недоступен, но `tasker mcp start` работает.

## Windows

**Демон.** Супервизор, который заменяет рабочий процесс без простоя, по умолчанию выключен: `tasker-mcpd` работает одним процессом, а `tasker mcp upgrade` просто перезапускает демон. Включить: переменная `TASKER_MCP_SUPERVISOR=1` в окружении `tasker mcp start` или аргумент `tasker-mcpd --supervised`.

**Имена файлов.** Название в имени файла состоит из букв, цифр и дефисов, поэтому запрещённые знаки Windows (`< > : " / \ | ? *`), завершающие точка и пробел и зарезервированные имена (`CON`, `NUL`, `COM1`…) в имя не попадают.

**Длина пути.** Самый длинный файл занимает до 144 знаков внутри рабочей папки. Tasker открывает и пути длиннее 260 знаков, а `git` без `core.longpaths` и проводник — нет. Если путь рабочей папки длиннее 114 знаков, при открытии пишется предупреждение; держите папку ближе к корню диска или включите `git config core.longpaths true`.

**Переводы строк.** Tasker пишет файлы с LF без BOM, а читает и с CRLF, и с BOM; версия сущности считается по тексту с LF, поэтому `core.autocrlf=true` не вызывает ложных конфликтов правки. Чтобы git не подменял окончания, добавьте в репозиторий `.gitattributes`:

```
/.tasker/** text eol=lf
```

Хуки `tasker hooks install` пишутся с LF и запускаются через `sh` из Git for Windows.

**Кодировка и PowerShell.** В окне консоли `tasker` переключает кодовую страницу на UTF-8 и возвращает её при выходе; при перенаправлении вывода пишет UTF-8 без BOM. Если кириллица в выводе искажается, задайте `[Console]::OutputEncoding = [Text.Encoding]::UTF8`. `~` в путях раскрывает сам `tasker`. Работают Windows Terminal, PowerShell 7, Windows PowerShell 5.1 и cmd.exe; автодополнение: `tasker completion pwsh` (подробнее: [Консоль](Консоль)).

Ограничения: Windows не проверялась на реальной системе, поэтому считайте её поддержку экспериментальной.
