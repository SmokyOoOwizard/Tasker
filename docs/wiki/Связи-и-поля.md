# Связи и поля

Типизированные связи между задачами (в том числе эпики) и свои поля типов и задач. Основы — [Концепции](Концепции).

## Связи

Связь — «задача A —тип→ задача B» в одном проекте. У типа два названия, по одному на сторону: A видит `blocks`, B — `is blocked by`. Связь с собой и повтор связи не допускаются.

| Тип по умолчанию | Названия сторон | Циклы |
|---|---|---|
| Blocks | blocks / is blocked by | запрещены |
| Duplicate | duplicates / is duplicated by | разрешены |
| Cloners | clones / is cloned by | разрешены |
| Relates | relates to / relates to | нет направления |
| Problem/Incident | causes / is caused by | разрешены |
| Parent/Child | includes / is part of | запрещены, иерархический |

Типы можно менять, удалять и добавлять свои; тип с существующими связями не удаляется.

| Команда | Что делает |
|---|---|
| `tasker link-type list \| get \| update \| delete` | Типы связей проекта |
| `tasker link-type create <имя> --outward … [--inward …] [--allow-cycles true\|false] [--hierarchical true\|false]` | Новый тип; без `--inward` связь без направления |
| `tasker task link TSK-5 blocks TSK-7` | Связь; `TSK-7 "is blocked by" TSK-5` — то же самое |
| `tasker task unlink TSK-5 blocks TSK-7` | Снимает связь |
| `tasker task links TSK-5` | Исходящие и входящие связи (их показывает и `task get`) |

Тип в `task link` — его имя или название любой стороны.

**Циклы.** При `allowCycles: false` связь, замыкающая цепочку одного типа, отклоняется с путём (`Error: Cycle: TSK-3 → TSK-2 → TSK-3 …`). Циклы, появившиеся после слияния веток git, `tasker sync` и `tasker cleanup` только сообщают; связь снимают вручную ([Хранение и git](Хранение-и-git)).

## Иерархия: эпик и вложенные задачи

Признак типа `hierarchical` делает источник связи родителем, а цель потомком; по умолчанию это `Parent/Child`. Эпик — любая задача с потомками, а не отдельный тип. Родителей может быть несколько, циклы запрещены всегда.

```
tasker task create "Вход по паролю" --type Task --parent TSK-5
tasker task update TSK-7 --add-parent TSK-5 --remove-parent TSK-3
tasker task list            # потомки под родителем с отступом
tasker task list --flat     # плоский список
```

- `--parent` равносильно `task link TSK-5 includes TSK-7`; при нескольких иерархических типах нужен `--parent-type`.
- Фильтры действуют на каждую задачу отдельно: подошедший потомок неподходящего эпика идёт на верхнем уровне.
- Задача с несколькими родителями показана под каждым, повторы помечены `(+)`.
- `--offset`/`--limit` считают задачи верхнего уровня с поддеревьями.
- `--json`, REST и MCP плоские, с `parentIds` и `childCount`; доски дерево не строят.

## Поля

Поле описывают в каталоге проекта, затем подключают к типам или добавляют задачам.

| Свойство | Значения |
|---|---|
| Имя | Только буквы и цифры любого алфавита, уникально без учёта регистра |
| Тип | `string`, `int`, `float`, `bool`, `date`, `enum` |
| Несколько значений | `--multiple`; без повторов |
| Перечисление | Для `enum`: список значений проекта |

Значения приводятся к каноническому виду (`007` → `7`); `date` — `yyyy-MM-dd`, `enum` — название или id, `string` — до 2000 знаков.

| Команда | Что делает |
|---|---|
| `tasker field create <имя> --type enum --enum <перечисление> [--multiple]` | Поле каталога (`list`, `get`, `update`, `delete`) |
| `tasker enum create <имя> --value A B C` | Перечисление; `enum update` — `--add-value`, `--remove-value`, `--rename-value Старое=Новое`, `--values` |
| `tasker task-type create\|update … --field Имя[:required]` | Поля типа (при `update` список заменяется; есть `--add-field`, `--remove-field`) |
| `tasker task create\|update … --field Имя=значение` | Значение; у множественного ключ повторяют, `Имя=` очищает |
| `… --add-field Имя`, `--remove-field Имя` | Подключить поле без значения / убрать дополнительное или собственное |
| `… --custom-field Имя:тип[:required][:multiple][:enum=Перечисление][=значение]` | Собственное поле задачи, напр. `Tags:string:multiple=a` |

Три вида полей у задачи:

- поле типа есть у каждой задачи типа, не удаляется и может быть обязательным (`Level:required`);
- дополнительное — поле каталога, добавленное одной задаче;
- собственное — определено в самой задаче и не меняется: нужно другое — пересоздайте.

Обязательность проверяется при создании задачи и правке содержимого (заголовок, описание, тип, поля); смена статуса и перенос по доске её не проверяют.

## Фильтры по полям

`--field` в `task list`, `board show`, `board tasks` (и в `--column-filter`, см. [Концепции](Концепции#доски-и-колонки)) работает по полям каталога и собственным полям; условия объединяются по «и».

| Условие | Смысл |
|---|---|
| `Имя=значение`, `Имя!=значение` | Равно / ни одно значение не равно (подходят и задачи без значения) |
| `Имя>3`, `>=`, `<`, `<=` | Только `int`, `float`, `date` |
| `Имя:set`, `Имя:unset` | Значение есть / нет |
| `Имя:attached`, `Имя:detached` | Поле подключено к задаче (типом или как дополнительное) / нет |

```
tasker task list --field 'Estimate>=3' --field Level=high
```

- Значение приводится как при записи (`Level=high` найдёт `High`); диапазона нет — берут два условия.
- У множественного поля `=` и сравнения означают «хотя бы одно значение подходит».
- `>` и `<` оболочка читает как перенаправление: условие в кавычках (PowerShell — одинарные, cmd.exe — двойные); `!=` в bash/zsh — одинарные.

## Удаление и смена полей

| Действие | Если используется |
|---|---|
| Удалить поле или перечисление | Отказ (`In use`) пока они подключены к типу, записаны у задачи или стоят в условии колонки |
| Убрать поле из типа | `--drop-values` (стереть значения) или `--keep-values` (поле остаётся дополнительным) |
| Убрать значение перечисления | `--drop` (стереть у задач, снять условие с колонок) или `--replace-with <значение>` |
| Сменить тип поля | Без потерь: любой → `string`, `int` → `float`, `string` → `int`/`float`/`bool`/`date`/`enum`; прочее через `string`. Непреобразуемое: `--clear-unconvertible` или `--map Старое=Новое`; несколько значений → одно: `--several keep-first\|clear` |

Без выбора команда сообщает число затронутых задач и ничего не меняет.
