# Концепции

Tasker хранит данные в **рабочей области** (папка `.tasker` или файл SQLite). В ней лежат проекты, а всё остальное принадлежит одному проекту.

## Сущности проекта

| Сущность | Что это |
|---|---|
| Статус | Название шага (`Todo`, `Done`…), необязательные цвет и описание. |
| Набор статусов | Упорядоченный список статусов — путь, по которому идёт задача. |
| Тип задачи | Имя, описание и один набор статусов; может подключать [поля](Связи-и-поля). |
| Серия | Нумерация задач с префиксом: ссылки `TSK-1`, `TSK-2`… |
| Доска | Колонки поверх статусов (и, при желании, значений полей). |
| Тип связи, поле, перечисление | См. [Связи и поля](Связи-и-поля). |
| Задача | Заголовок, описание, тип, статус, номера в сериях, связи, значения полей. |

Правила и зависимости:

- Задачу нельзя создать без типа, а тип — без набора статусов. Новый проект пуст: сначала статусы, набор, тип, затем доска (пошагово — [Быстрый старт](Быстрый-старт)).
- Статус задачи обязан входить в набор её типа. Без `--status` берётся первый статус набора.
- Статус, набор и тип удаляются, только если ими никто не пользуется (набор — типами и досками, тип — задачами).
- Любую сущность указывают по имени или id; задачу ещё и ссылкой `TSK-5`.
- У статусов и типов задач есть описание (`-d`): правила вроде «когда Баг, а когда R&D» лежат рядом с данными, а агенты читают их через [MCP](MCP-и-агенты). Пустое `-d ""` очищает.

## Серии и ссылки

Серия даёт задачам проекта номера 1, 2, 3… Задачу можно указать идентификатором или ссылкой `ПРЕФИКС-номер`; ссылка удобна в коммитах и ветках.

- Префикс: латинские буквы и цифры, до 20 символов, уникален в проекте, регистр важен (`TSK` и `tsk` — разные серии).
- Серий в проекте может быть несколько, они не зависят от типа. Задача бывает вне серий, в одной или в нескольких (по номеру в каждой).
- Номер новой задачи — наибольший номер серии плюс один; номер удалённой задачи с максимальным номером выдают заново.
- Удаление серии убирает ссылки на неё из задач.
- Если две ветки git выдали один номер, обе задачи остаются, помечены как конфликт номера и исправляются через `tasker cleanup --resolve-conflicts` ([Хранение и git](Хранение-и-git)).

| Команда | Что делает |
|---|---|
| `tasker series create <название> --prefix <префикс>` | Создаёт серию |
| `tasker series list`, `get <серия>` | Показывает серии |
| `tasker series update <серия> [--name] [--prefix]` | Переименовывает |
| `tasker series delete <серия>` | Удаляет серию |
| `tasker series add-task <серия> <задача>` | Добавляет существующую задачу в серию |
| `tasker series remove-task <серия> <номер>` | Убирает задачу из серии |
| `tasker series renumber-task <серия> <задача> [--to N]` | Меняет номер (без `--to` — следующий свободный) |
| `tasker task create … --series TSK` | Создаёт задачу сразу в серии (ключ повторяется) |

`<серия>` — id или префикс.

## Жизненный цикл задачи

```
tasker task create "Починить вход" --type Task --series TSK    # статус — первый в наборе типа
tasker task update TSK-1 --status Doing                         # смена статуса
tasker task update TSK-1 --title "…" -d "…"                     # правка содержимого
tasker task delete TSK-1
```

- Создание: нужен тип; в каждой серии задача получает номер; обязательные поля типа должны быть заполнены ([Связи и поля](Связи-и-поля)).
- Смена статуса — любой статус из набора типа, порядок не навязывается. Обязательность полей при этом не проверяется.
- При смене типа статус должен входить в набор нового типа; иначе укажите подходящий тут же: `--type Task --status Doing`.
- Правки идут по версии: если сущность изменили после чтения, операция отклоняется («modified»). Сущность можно заблокировать на время правки (`tasker lock`, блокировка истекает через 2 минуты).

## Доски и колонки

Доска показывает задачи тех типов, чьи наборы статусов указаны в ней. **Колонка** — это один или несколько статусов и, по желанию, условия по полям. Задача лежит в колонке, если её статус входит в колонку и выполнены все условия; отдельного «переноса» нет.

```
tasker board create Main --status-set Basic \
  --column "To do=Todo" --column "Doing=In progress" --column "Done=Done"
tasker board show Main
tasker board tasks Main Doing
```

- Перенос задачи в колонку — это смена статуса на **первый** статус колонки, который есть в наборе типа задачи. Через CLI то же делает `task update --status`; в интерфейсе — перетаскивание, в MCP — `move_task`.
- Условия колонки пишут как фильтр `task list --field` ([Связи и поля](Связи-и-поля#поля)), перед ним — название колонки: `--column-filter "Doing:Estimate>=3"`. Несколько условий — «и»; `--column-filter "Doing:"` снимает условия.
- Правка поля задачи сама перемещает её в другую колонку. Перенос в колонку, под условия которой задача не подходит, отклоняется: сначала поправьте поля.
- Один статус можно дать нескольким колонкам, только если их условия не могут выполняться вместе (`Component=API` и `Component!=API`, `Estimate>=3` и `Estimate<3`, `:set` и `:unset`); иначе доска не принимается.
- Поле, на которое ссылается колонка, нельзя удалить или сменить его тип; переименовать можно.
- Задачи со статусом вне колонок на доске не видны, но есть в `task list`. `board show` по умолчанию выводит до 50 задач на колонку (`--limit`, `--all`).

## Проект по умолчанию

Команды внутри проекта берут его в таком порядке: ключ `-p/--project` (имя или id), переменная `TASKER_PROJECT`, единственный проект области. Проектов несколько и ничего не задано — ошибка «Project is required». В [MCP](MCP-и-агенты) аргумент проекта можно опустить, если агенту доступен ровно один проект.
