# Демон MCP

Демон (`tasker-mcpd`, его запускает `tasker`; программа на .NET) — фоновый процесс, который держит один MCP-адрес `http://127.0.0.1:<порт>/mcp` сразу для нескольких рабочих областей. Он не зависит от терминала (переживает его закрытие) и может стартовать при входе в систему. Что агент видит по этому адресу — в [MCP-и-агенты](MCP-и-агенты).

## Команды

| Команда | Что делает |
|---|---|
| `tasker mcp start` | запуск в фоне; показывает адрес и области |
| `tasker mcp stop` | остановка |
| `tasker mcp restart` | перезапуск (применяет смену порта); вызовы в работе обрываются |
| `tasker mcp status` | порт, процессы, области, автозапуск; код выхода 3, если демон не работает |
| `tasker mcp run` | в этом терминале до Ctrl+C |
| `tasker mcp upgrade` | переход на новую сборку без простоя |
| `tasker mcp autostart enable\|disable` | автозапуск при входе в систему |

Пока автозапуск включён, демоном владеет система: `start` и `stop` идут через неё, а `stop` действует до следующего входа. Включение автозапуска забирает у системы вручную запущенный демон; выключение работающий не останавливает.

## Порт и области

Демон разрешает агентам только перечисленные области; настройки действуют сразу, без перезапуска (кроме порта).

```bash
tasker mcp workspace add ~/work/project-a   # папка с .tasker
tasker mcp workspace add ~/data/tasker.db   # или существующий файл SQLite (та же база, что у сервера)
tasker mcp workspace list
tasker mcp workspace remove ~/work/project-a
tasker mcp port 5719                        # показать или задать порт; применится после restart
tasker mcp config                           # файл настроек, порт, число областей
```

- Порт по умолчанию `5719`, слушается только `127.0.0.1`.
- Настройки — `settings.json` (раздел `mcp`: `port`, `workspaces`) в каталоге данных, общий у консоли и демона: macOS `~/Library/Application Support/Tasker`, Linux `~/.local/share/Tasker`, Windows `%LOCALAPPDATA%\Tasker`; `TASKER_HOME` меняет каталог.
- Область-файл SQLite называется по имени файла (`tasker.db`); её можно одновременно открывать сервером и демоном — запись идёт транзакциями SQLite. Проблем файлов (`list_workspace_problems`) у неё нет.
- Область, которую не удалось открыть (папку удалили, диск не подключён), не мешает остальным: в `status` она `failed`, повтор раз в 30 с и при изменении настроек.
- Один демон на пользователя: второй `run` отказывается.

## API областей

Кроме MCP демон отдаёт API каждой открытой области по адресу `http://127.0.0.1:<порт>/w/<имя области>/api/…` (имя — `key` из `tasker mcp status --json`; у одноимённых папок с суффиксом, `Tasker-2`). Входа нет, запросы принимаются только с этой машины. Так с демоном работает приложение для macOS.

- Чтение — GraphQL: `POST …/api/graphql`, схема `graphql/schema.graphql`.
- Живые изменения — подписка `workspaceChanges` по тому же адресу: ответ идёт потоком `text/event-stream` с пингами раз в 20 с.
- Изменения — REST (`POST`, `PATCH`, `DELETE`), описан в `docs/api/openapi.json`.

## Автозапуск

| Система | Механизм | Особенности |
|---|---|---|
| macOS | агент launchd `~/Library/LaunchAgents/com.technotronika.tasker.daemon.plist`, его ставит `Tasker.app` | запуск при входе, перезапуск при падении, пока файл программы существует; демон из удалённого приложения уходит сам ([Установка](Установка)) |
| Linux | пользовательская служба systemd `~/.config/systemd/user/tasker-mcp.service` | перезапуск при падении; без входа в систему нужен `loginctl enable-linger`; нужен сеанс пользователя systemd |
| Windows | задача Планировщика заданий «Tasker MCP» | текущий пользователь, права администратора не нужны, окно не показывается |

Особенности систем: [Платформы](Платформы).

## Обновление без простоя

`tasker mcp restart` закрывает порт на несколько секунд и обрывает вызовы. `tasker mcp upgrade` заменяет сервер на новую сборку на лету: порт остаётся открытым, вызовы не отклоняются.

```bash
tasker mcp upgrade                 # замена на лету
tasker mcp upgrade --timeout 120   # сколько ждать, пока новый процесс откроет области (по умолчанию 60 с)
tasker mcp upgrade --restart       # жёстко: остановить и запустить
```

- Замена: рядом со старым стартует новый, открывает области; затем ему передаётся приём соединений, а старый дорабатывает начатые вызовы и выходит.
- Устройство: `tasker-mcpd` — маленький супервизор, который держит порт, и рабочий процесс, который обслуживает вызовы; `upgrade` меняет рабочий процесс, супервизор остаётся прежним до `restart` (или перезагрузки). Супервизор и рабочий процесс понимают друг друга между сборками: поэтому обновление идёт тем же `upgrade`, без простоя ([Установка](Установка#обновление-и-удаление)).
- Неудача (новый не поднялся, не открыл область, не уложился в `--timeout`) — старый продолжает работать, команда печатает причину и завершается с ненулевым кодом. Установщик в этом случае демон не перезапускает и подсказывает `tasker mcp upgrade --restart`.
- Windows: по умолчанию `upgrade` перезапускает демон; бесшовный режим включается `TASKER_MCP_SUPERVISOR=1` ([Платформы](Платформы)).

## Статус, логи, порт занят

- `tasker mcp status` показывает процессы демона и области (`open`, `opening`, `failed`).
- Журнал: `logs/mcp-<дата>.log` в каталоге данных, 7 дней. Если демон не поднялся, `start` показывает причину из журнала.
- Порт занят (`Port … is busy`): закройте занявшую программу или смените порт `tasker mcp port <номер>` и сделайте `tasker mcp restart`.
