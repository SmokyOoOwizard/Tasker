# Подключить агента

Дать агенту (Claude Code и другим клиентам MCP) доступ к вашим рабочим областям через общий MCP-адрес.

## Что нужно

Запущенный демон MCP с разрешённой рабочей областью (`tasker manual install-daemon`) или десктоп с открытой вкладкой папки. Адрес один на все области: `http://127.0.0.1:5719/mcp` (порт 5719, если не менялся: `tasker mcp port`).

## Шаги

Разрешить область и запустить демон:

```bash
tasker mcp workspace add ~/work/project-a
tasker mcp start
```

Подключить агента в Claude Code (команда `claude`, не `tasker`):

```text
claude mcp add --transport http tasker http://127.0.0.1:5719/mcp
```

Чтобы агент действовал от своего имени, создайте его и передайте его id заголовком:

```bash
tasker agent create reviewer
tasker agent list
```

```text
claude mcp add --transport http tasker http://127.0.0.1:5719/mcp --header "X-Tasker-Agent: <id агента>"
```

## Пример

Какую область использовать, агент указывает необязательным аргументом `workspace` любого инструмента: имя папки (как в инструменте `list_workspaces`) или её путь. Одна область — аргумент не нужен.

```text
list_workspaces
list_tasks {"workspace": "project-a"}
```

## На что обратить внимание

- Агент видит только области, разрешённые командой `tasker mcp workspace add`; других папок он открыть не может. `tasker mcp workspace list` показывает, что разрешено.
- Если областей несколько, а `workspace` не передан, инструмент отвечает ошибкой со списком доступных.
- Без заголовка `X-Tasker-Agent` вызовы идут от локального агента `agent` выбранной папки; id агента проверяется в области: в другой папке он неизвестен.
- Адрес слушает только `127.0.0.1`: доступ только с этой машины, без токена.
