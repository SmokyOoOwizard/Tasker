# Sync и cleanup после git

После `git pull`, `checkout` или слияния: обновить кэш, увидеть проблемы и убрать битые ссылки.

## Что нужно

Папка `.tasker` в репозитории git. Файлы `.tasker` — источник правды, кэш (индекс) пересобираемый.

## Шаги

Обновить кэш сразу после команды git и увидеть нечитаемые файлы (конфликт слияния):

```bash
tasker sync
```

Чтобы кэш обновлялся сам после pull, checkout, merge и rebase, поставьте git-хуки один раз в каждом клоне:

```bash
tasker hooks install
tasker hooks status
```

Убрать то, на что сверка пожаловалась: ссылки на несуществующие серии, связи на удалённые задачи и типы, дубликаты номеров.

```bash
tasker cleanup --dry-run
tasker cleanup
tasker cleanup --resolve-conflicts
```

## Пример

```text
$ tasker cleanup --dry-run
Nothing is written (dry run):
Nothing to clean up
```

## На что обратить внимание

- `sync` и хуки только сообщают о проблемах, ничего не пишут: пишет только `cleanup`.
- Циклы связей (A blocks B и B blocks A после слияния веток) `sync`, `cleanup --check` и демон показывают строкой `Link cycle: …`, но `cleanup` их не удаляет: снимите связь сами, `tasker task unlink`. Подробнее: `tasker manual links`.
- `cleanup --resolve-conflicts` ещё решает дубликаты номеров: номер сохраняет самая ранняя задача, остальные получают следующие номера. Без этого параметра дубликаты остаются.
- `cleanup --check` ничего не пишет и завершается кодом 2, если есть что чистить (для CI). Он ничего не делает, пока среди файлов есть нечитаемые (конфликт git): сначала разрешите конфликт; не работает и посреди слияния, rebase, cherry-pick.
- Если демон MCP обслуживает папку, `sync` просит его; иначе сверяет сама (в выводе `via daemon` или `via direct`).
- Хуки не срабатывают после `git reset --hard`, `stash pop` и слияния с конфликтом: запустите `tasker sync` вручную.
