# Golden-корпус: эталоны поведения консоли и демона MCP

Снято с .NET-сборки 0.1.0 скриптом `scripts/golden/generate.py` (TSK-124). Rust-реализация (`tasker-core`, `tasker-files`, `tasker-cli`, `tasker-mcpd`) обязана
воспроизводить всё, что здесь лежит, байт в байт — для `--json`, файлов `.tasker` и MCP строго, для текстового вывода консоли
построчно.

## Что внутри

| Путь | Что это |
|---|---|
| `workspace/.tasker/` | Каноническая рабочая область: проект **Golden** (все сущности, все типы полей, «опасные» строки, иерархия, связи всех типов, две серии, доски с условиями колонок, пользователи и агенты) и проект **Legacy** (файлы formatVersion 0–8, имена `<guid>.yaml`, CRLF, BOM, файл с маркером конфликта git, файл формата 99 «из будущего»). Без `.cache` — индекс строится заново. |
| `versions.json` | Версия каждого файла области: первые 16 hex SHA-256 от байтов без BOM и с CRLF→LF (`Tasker.Core.IO.LineEndings.ForHash`). Так же версии показывают `task get --json`, MCP и REST. |
| `yaml-style/titles.json`, `yaml-style/descriptions.json` | Стилевые эталоны YamlDotNet 18.1: значение строки и то, как она записана в файл (кавычки `'`/`"`, `|-`, `|`, `|+`, `|2-`, экранирование). Это спецификация собственного YAML-эмиттера в Rust. |
| `expected/cli/NNN-<имя>.{args,out,err,code}` | Вывод команд консоли на копии области: аргументы (по одному в строке, путь области — `<ROOT>/golden`), stdout, stderr, код выхода. Списки и `get` всех сущностей в тексте и `--json`, фильтры и сортировки `task list`, `sync`, `cleanup --check`, `migrate --check`/`--dry-run`, блокировки, ошибки, справка каждой команды (`help-*`), `completion <shell>`, директива `[suggest:N]`, `manual`. |
| `expected/migrate/` | `tasker migrate` на копии области: вывод команды, повторный `migrate --check` (код 2 — остаются файл с конфликтом и файл формата 99), `tasker/` — вся область после миграции, `versions.json` — версии файлов после неё. |
| `expected/mcp/` | Снапшоты демона MCP: `initialize`, `tools-list.json` (имена, описания, inputSchema всех инструментов; `tool-names.txt` — список), ответы инструментов на чтение, `errors/` — по ответу на каждый код ошибки; `cli/` — `tasker sync` (текст, `--json`, `-q`) при работающем демоне, который обслуживает область: сверяет демон, вывод `via daemon` (TSK-160). |
| `autostart/` | Файлы автозапуска .NET-генераторов — launchd plist, systemd unit, XML Планировщика (UTF-16 LE с BOM) — и вызываемые команды; см. `autostart/README.md` (TSK-140). |
| `sqlite/` | Раздел SQLite (TSK-159, `generate.py --only sqlite`): та же последовательность создания сущностей .NET-консолью с `--sqlite` (проекты Golden и Legacy без файловых особенностей). `workspace.sql` — база SQL-дампом (схема в порядке `sqlite_master`, строки по `rowid`; при сверке восстанавливается в WAL); id (в столбцах-Guid — заглавными, в значениях полей — строчными) и время (`yyyy-MM-dd HH:mm:ss.FFFFFFF`) канонизированы SQL-запросами по тем же правилам, что у папки; `schema.sql` — `.schema` базы, созданной `EnsureCreated` (с ним сверяется и новая база, созданная проверяемой сборкой, и тест `db_schema` Rust); `expected/cli` — вывод тех же команд консоли с `--sqlite <ROOT>/golden.db` (без справки и автодополнения); `expected/mcp` — демон с областью `kind: sqlite` (`golden.db`): чтение, ошибки, правка через MCP. |
| `index/` | Раздел index (TSK-161, `generate.py --only index`): кэш индекса `.tasker/.cache/index.db`, общий у .NET и Rust. Снят .NET-консолью: `tasker sync -w <копия workspace/>` (без `.cache`), затем `schema.sql` — `.schema` базы (у таблиц `CREATE TABLE IF NOT EXISTS`, как печатает оболочка `sqlite3`), `index.txt` — канонический дамп: `user_version`, режим журнала, строки таблиц `files` (по `path`), `task_series`, `task_links`, `task_fields`, `task_field_values` (по `path` и `rowid`) через `quote()`, `mtime` — `<MTIME>`, если он равен времени изменения файла в тиках .NET (иначе число и расхождение), и содержимое `.cache` после выхода процесса. `--verify` строит индекс проверяемой сборкой и сравнивает оба файла байт в байт; тест `tasker-files/tests/index.rs` делает то же в `cargo test`. Пути в дампе относительные — `<ROOT>` не нужен. |
| `notes.json` | Чем сгенерировано, канонические id проектов, id особых файлов (конфликт, «из будущего»), отвергнутые консолью строки. |

## Канонизация

Консоль сама выдаёт случайные id и текущее время, поэтому после создания области скрипт приводит их к детерминированным:

- id проектов — `11111111-…` (Golden) и `22222222-…` (Legacy); id типов связей по умолчанию пересчитаны по правилу
  `DefaultLinkTypes.IdOf` (MD5 от `tasker-link-type:<projectId>:<key>`, конструктор `Guid(byte[])` — little-endian), поэтому
  корпус заодно проверяет и это правило;
- остальные id — `NNNNNNNN-0000-4000-8000-NNNNNNNNNNNN` по порядку обхода (папка, имя сущности); имена файлов `<slug>-<id8>.yaml`
  переименованы под новые id;
- временные метки — от `2026-01-01T00:00:00` с шагом 61 с в порядке исходных (порядок создания сохранён).

Что остаётся недетерминированным и заменяется в снапшотах: путь временного каталога → `<ROOT>`; id областей демона
(12 hex SHA-256 от `Files:<канонический путь>`) → `<WSID:golden>`, `<WSID:broken>`; id, время создания и версия локального
агента MCP (создаётся демоном при первом вызове) → `<LOCAL-AGENT-*>`; срок блокировки правки → `<TIME>`.

## Как сверить и как переснять

```bash
scripts/golden/generate.py --verify --diff    # собрать Rust (cargo build --release), снять эталоны заново и сравнить с корпусом
scripts/golden/generate.py --verify --bin <каталог>   # то же с готовыми tasker и tasker-mcpd
scripts/golden/generate.py --bin <каталог> --only index   # переснять раздел (или весь корпус без --only) этой сборкой
```

`--verify` — главный инструмент: он берёт `workspace/` из корпуса, прогоняет те же команды консоли, `migrate` и вызовы MCP
проверяемой сборкой и печатает различия. Корпус снят с .NET-сборки 0.1.0 и меняется только вместе с поведением: переснять его
можно лишь явной сборкой (`--bin`), чьё поведение принимается за эталон, — без `--bin` скрипт только сверяет.

Ничего в настоящей установке скрипт не трогает: `TASKER_HOME`, область и демон (на свободном порту) живут во временном
каталоге и удаляются в конце (`--keep` — оставить для разбора).

## Известные особенности, зафиксированные корпусом

- `task get <id>` файла с маркером конфликта слияния падает необработанным исключением YamlDotNet (TSK-144); снапшот
  не снимается, пока не исправлено — исправление добавит его в `generate.py`.
- Ошибку `[unavailable]` (область ещё открывается) детерминированно не снять — она зависит от времени; текст в
  `src/Tasker.Mcp/WorkspaceArgument.cs`.
- Описание с CRLF внутри (`Description: crlf`) консоль нормализует в LF до записи.
- Расхождение сборки с корпусом — ошибка; намеренное изменение поведения меняет и корпус (в том же изменении).
