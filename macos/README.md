# Tasker для macOS

Нативное приложение на SwiftUI + AppKit. Минимальная версия macOS — 14 (Sonoma), Swift 6 со строгой проверкой конкурентности.

## Как устроен проект

Файл `Tasker.xcodeproj` в git не хранится: он создаётся из описания `project.yml` инструментом [XcodeGen](https://github.com/yonaskolb/XcodeGen). Так параллельные ветки не конфликтуют в `project.pbxproj`, а новые файлы из `Sources/` и `Tests/` подхватываются сами.

- `Sources/Tasker` — приложение (bundle id `com.technotronika.tasker`);
- `Tests/TaskerTests` — тесты на Swift Testing;
- версия берётся из файла `VERSION` в корне репозитория, номер сборки — число коммитов.

## Требования

- Xcode 16 или новее;
- XcodeGen: `brew install xcodegen`.

## Команды

Из корня репозитория:

```bash
scripts/macos-build.sh generate
```

Создаёт `macos/Tasker.xcodeproj`, после чего его можно открыть в Xcode.

```bash
scripts/macos-build.sh build
```

Собирает отладочную версию в `macos/build/Build/Products/Debug/Tasker.app`.

```bash
scripts/macos-build.sh test
```

Запускает тесты.

```bash
scripts/macos-build.sh run
```

Собирает и запускает приложение.

```bash
scripts/macos-build.sh release
```

Собирает релизную версию.

## Демон

Демон `tasker-mcpd` входит в состав приложения: `scripts/macos-build.sh` собирает его (`dotnet publish`, нужен .NET SDK) в `macos/build/daemon`, а Xcode кладёт в `Tasker.app/Contents/Helpers`.

- приложение само ставит агент launchd `com.technotronika.tasker.daemon` (`~/Library/LaunchAgents`) на встроенный демон: он стартует при входе, а после падения или `tasker mcp stop` launchd поднимает его снова;
- к уже работающему демону приложение подключается по файлам состояния (`~/Library/Application Support/Tasker/mcp/daemon.json`, `daemon.lock`), как консоль; `TASKER_HOME` меняет каталог;
- версия активного рабочего процесса демона из `/daemon/status` должна совпасть с версией приложения. Иначе работа блокируется, пока пользователь не нажмёт «Обновить демон»: замена на лету через `/daemon/upgrade`, а демон старой сборки без супервизора останавливается и запускается встроенный;
- состояние (работает / запускается / не работает) показано в сайдбаре; подключение повторяется с паузами 2, 5 и 10 секунд.

Подпись и нотаризация демона внутри релизного `.app` — отдельная задача.

## Рабочие области и проекты

- Вкладки вверху окна — открытые папки. У вкладки свой идентификатор, поэтому одну область можно открыть в нескольких вкладках и окнах. Окна, их вкладки, выбранная вкладка, рамки окон и недавние папки хранятся в настройках приложения (`UserDefaults`, ключ `workspaceLayout`, модель `WorkspaceLayout`) и восстанавливаются при запуске. Старый ключ `workspaceTabs` один раз переносится в одно окно. При первом запуске вкладками становятся все области, которые уже знает демон.
- У вкладки своё состояние (`WorkspaceTabSession`): раздел, проект, режим, сортировка и колонки списка, раскрытые строки, прокрутка, выделение, карточка, peek, история переходов, окно создания и сообщения о своих действиях. Новая вкладка берёт настройки списка у последних изменённых для этого проекта.
- Несохранённый текст редакторов карточки (название, описание, поля) хранится в памяти вкладки и возвращается в редактор при смене вкладки и переносе в другое окно. Закрытие вкладки или окна с таким текстом требует подтверждения. После выхода из приложения текст не сохраняется.
- Общие на приложение: подключение к демону, список открытых папок и живая подписка. Подписка одна на область (`WorkspaceSessions`): она пишет в общий кэш клиента области и держится, пока открыта хотя бы одна вкладка этой области. Сообщения о чужих изменениях видны во всех окнах этой области.
- Вкладка переносится перетаскиванием: на полосу другого окна, в новое окно (отпустить вне окон) или на другое место своей полосы. Отпускание внутри своего окна и Esc отменяют перенос. Те же действия есть в меню «Окно» и по правому щелчку на вкладке; там же «Объединить все окна», следующая и предыдущая вкладка (⌃Tab, ⌃⇧Tab). «Файл»: новая вкладка той же области ⌘T, новое окно ⌘⇧N, закрыть вкладку ⌘W, закрыть окно ⌘⇧W. Системные вкладки macOS отключены.
- Последняя вкладка закрывает окно, если есть другие окна; единственное окно остаётся пустым с кнопкой «Открыть папку…». Закрытие окна закрывает все его вкладки, они попадают в «Недавние». Выход из приложения вкладки не закрывает: при запуске они восстанавливаются.
- «Открыть папку…» добавляет папку в `settings.json` демона (раздел `mcp.workspaces`, под блокировкой `settings.lock`, как делает `tasker mcp workspace add`; остальные настройки сохраняются) и открывает вкладку. Демон подхватывает изменение сам. Выбрали саму `.tasker` — берётся папка над ней; в папке без `.tasker` приложение сначала спрашивает.
- Закрытие вкладки только прячет её: область остаётся в демоне, агенты и консоль её видят. Скрытые и добавленные консолью папки доступны в меню «Недавние»; уже открытые области в том же меню открываются ещё одной вкладкой.
- Переключатель проектов в сайдбаре и «Новый проект…» работают на состоянии из TSK-187. Пока в проекте нет задач и не заведены статусы, набор статусов, тип задач и доска, вместо раздела показывается онбординг из четырёх шагов.

## Доски

Раздел «Доски» (⌘2) показывает доску проекта этой вкладки: колонки со статусами, чипы условий по полям, «N задач вне колонок» и по 50 карточек на колонку с «показать все». Состав колонок считает сервер (`columnTasks`), приложение его не пересчитывает.

- Перенос карточки: перетаскивание (AppKit: `NSDraggingSource` на карточке, `NSDraggingDestination` на полотне доски) или «Перенести в колонку» в контекстном меню. Приложение посылает `POST …/boards/{id}/columns/{columnId}/move`, статус выбирает сервер по правилу переноса колонки для набора статусов типа задачи. Карточка встаёт в колонку после ответа; отказ (`board.taskNotMatchColumn`, `board.noDropRule` и другие) приходит с кодом и параметрами, показывается локализованным сообщением, колонка трясётся, карточка остаётся на месте.
- Клик по карточке открывает всплывающее окно задачи, двойной клик — карточку; Esc закрывает окно. Доска живёт на уровне вкладки: те же `TaskNavigator`, живые обновления и палитра. Карточка сама переезжает при смене поля или статуса.
- Вход в редактор — кнопка «Редактор» и команда `editBoard` (⌥⌘E); выбор доски — в верхней панели и в палитре («Доска: …»).
- Строка запроса (TSK-190) подключается через `BoardQueryBar.query` и `BoardViewModel.fieldFilter` (условия `Имя=значение`, они передаются колонкам как `field`).

## Настройки проекта

Раздел «Настройки» (⌘3) открывается внутри вкладки и относится к проекту этой вкладки. Слева список подразделов (`SettingsPage`), справа содержимое. Новый подраздел — это новый случай `SettingsPage`, страница в `SettingsSection` и пункт палитры (он появляется сам).

- «Серии»: создание, переименование, удаление, состояние (конфликты номеров, одинаковые префиксы, нечитаемые файлы), разрешение конфликтов (тот же план и окно, что на странице серии), переход к задачам серии;
- «Типы связей»: стороны, направленность, циклы, иерархия; тип со связями сервер не удаляет, приложение показывает причину;
- «Поля»: создание, тип, множественность, перечисление; при смене типа с затронутыми задачами окно с вариантами «очистить», «сопоставить» (для нового enum), «оставить первое»; «Используется» перед удалением;
- «Перечисления»: значения списком с перестановкой (кнопки и перетаскивание), поиск, вставка списка строками; удаление используемого значения — стереть у задач или заменить;
- «Участники» — только когда сервер области сообщает режим server (`/api/health`);
- «Проект»: переименование и удаление с вводом названия.

Правка сущности берёт её блокировку на время открытого окна и продлевает каждые 40 секунд; блокировка снимается при закрытии окна, вкладки и при выходе. Чужая блокировка и устаревшая версия показываются в окне.

## Меню, сочетания клавиш и настройки приложения

- Все команды описаны в одном месте — `AppCommand` (`Sources/Tasker/Commands`): название, сочетание и условие доступности. Меню (`NavigationCommands`), палитра ⌘K (`PaletteCommands`) и справка берут их оттуда, а выполняет их один исполнитель `CommandRunner`. Новая команда — случай `AppCommand`, ветка в `CommandRunner.perform` и строка в `design/shortcuts.json`.
- Пункты действуют на активное окно и его выбранную вкладку. Недоступные в текущем контексте неактивны: «Задача» без выбранной задачи (в списке, в peek или в карточке), «Файл → Создать задачу» без проекта, «следующая вкладка» при одной вкладке. Состояние окна собирает `CommandRunner.state(window:)`, оно передаётся меню через `ActiveWorkspaceWindow.commands`.
- В меню только сочетания с ⌘ или ⌃: одиночная буква в пункте меню перехватывала бы ввод текста. Одиночные буквы макета заменены так: C — ⌘N, S — ⌥⌘S (в списке по-прежнему работает и S), L — ⌘L, P — ⌥⌘P, G T/G B/G S — ⌘1/⌘2/⌘3, B — вид списка ⌥⌘1/⌥⌘2/⌥⌘3, ? — ⌘? и ⌥⌘/. Строка запроса (/, Tab, Ctrl+Space) и фильтр (F) появятся с TSK-190, доски — с TSK-193; пустых пунктов для них нет.
- Конфликты с системой проверяет тест `AppCommandTests`: сочетания не повторяются и не занимают системные (⌘Q, ⌘H, ⌘M, ⌘Пробел, ⌘Tab, снимки экрана и т. д.) и стандартные клавиши правки.
- «Справка → Сочетания клавиш» (⌥⌘/) открывает окно со списком из `design/shortcuts.json`; «Справка → Справка Tasker» (⌘?) открывает страницу в справке macOS (`Resources/Tasker.help`). Обе создаёт `scripts/gen-shortcuts.py` (`Generated/ShortcutTable.swift` и справочная книга RU/EN), тест сверяет таблицу с сочетаниями команд.
- Настройки приложения (⌘,) — отдельное окно `Settings`: язык, тема и поведение при запуске. Это не настройки проекта из раздела «Настройки» (⌘3).
- Поведение при запуске (`StartupBehavior`): «Открыть окна и вкладки, как были» (по умолчанию), «Пустое окно с кнопкой „Открыть папку…“» и «Только последнюю открытую папку» (выбранная вкладка активного окна). Закрытые при старте вкладки остаются в «Недавних».

## Токены дизайна

Цвета двух тем, радиусы, отступы, размеры шрифтов, тени и контуры значков статусов лежат в `design/tokens.json` (значения взяты из `docs/mockups/web/main-design.html`). Скрипт `scripts/gen-design-tokens.py` создаёт из него:

- `macos/Sources/Tasker/Generated/DesignTokens.swift` — константы и описание значков статусов;
- `macos/Sources/Tasker/Assets.xcassets/Tokens/` — цвета для светлой и тёмной темы;
- `design/generated/tokens.css` — CSS-переменные (во фронтенд пока не подключены).

После правки `tokens.json` запустите `python3 scripts/gen-design-tokens.py`. Команда `python3 scripts/gen-design-tokens.py --check` падает, если сгенерированные файлы разошлись с источником; её выполняет CI (`.github/workflows/design-tokens.yml`).

В коде используются `DesignColor.<имя>.color`, `DesignRadius`, `DesignSpacing`, `DesignLayout`, `DesignTypography` и `StatusIconView(name:color:)`. Системные цвета и числа, вписанные вручную, в видах не применяются.

## Строки и языки

Интерфейс на русском и английском. Все строки лежат в `design/strings.json`: ключ вида `section.tasks`, у каждого два перевода (`ru`, `en`). Подстановки пишутся как `{0}`, множественные формы как `{0#задача|задачи|задач}` (у русского три формы, у английского две) — так же, как в словаре макета `docs/mockups/web/main-design.html`. Строки, которые есть и в макете, обязаны переводиться одинаково.

Скрипт `scripts/gen-strings.py` создаёт из файла:

- `macos/Sources/Tasker/Generated/Localizable.xcstrings` — String Catalog;
- `macos/Sources/Tasker/Generated/L10nKey.swift` — перечисление ключей.

После правки `strings.json` запустите `python3 scripts/gen-strings.py`. Команда `python3 scripts/gen-strings.py --check` падает, если нет перевода, не совпадают подстановки или формы, перевод разошёлся с макетом, сгенерированные файлы устарели или в коде Swift вписана строка интерфейса (`Text("…")`, кириллица и т. п.); её выполняет CI (`.github/workflows/design-strings.yml`).

В коде строки берутся через `@Environment(\.localizer)`: `l.string(.sectionTasks)`, `l.taskCount(5)`, `l.date(...)`, `l.number(...)`. Язык по умолчанию — системный (русский, если в системе русский, иначе английский). Внизу боковой панели кнопка с текущим языком (RU или EN) открывает список: «Как в системе», «Русский», «English». Выбор применяется сразу, а системные пункты меню macOS обновятся после перезапуска.

## Клиент API

Пакет `TaskerAPI` (Swift Package, подключён к приложению в `project.yml`) — клиент демона и сервера. Чтение идёт через GraphQL, живые изменения — через GraphQL-подписку, изменения — через REST.

- `TaskerEndpoint.local(port:workspace:)` — демон в режиме Local (`http://127.0.0.1:<порт>/w/<область>`, без входа); `TaskerEndpoint.server(_:session:)` — сервер, вход по JWT. `RESTClient.signIn(baseURL:login:password:)` возвращает `ServerSession`: она подставляет access-токен в GraphQL и REST, заранее обновляет истекающий, после ответа 401 обновляет его один раз и повторяет запрос, а при отказе в обновлении забывает сессию.
- `TaskerAPIClient(endpoint:)` собирает всё вместе: `graphQL.fetch(_:cachePolicy:)`, `graphQL.watch(_:)` (поток значений, который следит за кэшем), `graphQL.subscribe(_:reconnect:)` и `liveUpdates()` (подписка с переподключением, по событиям обновляет затронутое в кэше), `rest.perform { try await $0.createProject(...) }`.
- Нормализованный кэш `NormalizedCache`: одна запись на сущность (`__typename` + `id`), общая для всех запросов. Генератор сам добавляет эти поля в запросы.
- Ошибки сведены в `TaskerAPIError`: `conflict` (`modified` — изменено другим, `locked` — правит `heldBy`, `inUse`, `unsupportedFormat`), `notFound`, `forbidden`, `unauthenticated`, `badRequest` — с `Refusal` (код, параметры, чем используется, английский текст; см. `docs/api/README.md`). Приложение показывает отказ через `Localizer.refusal`, текст сервера не разбирает. Ошибки GraphQL без кода — `graphQL([...])`; `timedOut`, `network`. Отмена задачи даёт `CancellationError`.

Запросы GraphQL лежат в `TaskerAPI/GraphQL/*.graphql`. Скрипт `scripts/gen-graphql-client.py` проверяет их по `graphql/schema.graphql` (поля, аргументы, типы переменных, фрагменты) и создаёт Swift-типы в `Sources/TaskerAPI/Generated/GraphQL/`. REST-клиент создаётся из `docs/api/openapi.json` (без `executeGraphQL`) генератором swift-openapi-generator: `scripts/gen-openapi-client.sh` пишет его в `Sources/TaskerAPI/Generated/REST/`.

```bash
python3 scripts/gen-graphql-client.py
```

```bash
scripts/gen-openapi-client.sh
```

С флагом `--check` скрипты падают, если сгенерированный код разошёлся со схемой; их выполняет CI (`.github/workflows/macos-api-client.yml`).

Тесты пакета (`swift test --package-path macos/TaskerAPI`, они же входят в `scripts/macos-build.sh test`) работают на фикстурах. Проверка на запущенном демоне включается переменными окружения:

```bash
TASKER_LIVE_PORT=5719 TASKER_LIVE_WORKSPACE=<область> swift test --package-path macos/TaskerAPI --filter LiveDaemonTests
```

Тест создаёт в области временный проект и удаляет его.

## Живые обновления

Экраны обновляются сами, без действий пользователя.

- Источник — GraphQL-подписка `workspaceChanges`: `TaskerAPIClient.liveUpdates()` переподключается после обрыва (паузы от 0,5 до 5 секунд) и превращает событие в `LiveUpdate` (что изменилось, кто автор, когда).
- Состояние лежит в нормализованном кэше клиента, а экраны читают его через `graphQL.watch(_:)`. Событие о задаче или проекте — один точечный запрос этой сущности (`LiveTask`, `LiveProject`): её запись в кэше обновляется на месте, а у проекта сбрасываются только поля списков (`tasks`, `stats` и т. п.). Поэтому заново читаются лишь затронутые списки, а не весь экран. Событие `unknown` перечитывает всё загруженное.
- После переподключения пропущенные события не догоняются: кэш сбрасывается, и всё открытое перечитывается. `watch` отдаёт новое значение, только если данные действительно изменились.
- Автора правки сообщает сервер (`author { key name }`), если правка прошла через демон: REST — локальный пользователь (`local`), MCP — агент. Правки из консоли, git и вручную приходят без автора. Тосты о своих правках (`local`) не показываются.
- `LiveWorkspace` (в приложении) следит за первой открытой рабочей областью демона и показывает тосты, а в верхней панели — «подключение…» или «нет связи с демоном», пока связь не живая. Каждое событие увеличивает `LiveWorkspace.revision`, по нему перечитывается открытый список задач.

## Список задач

Раздел «Задачи» — `NSOutlineView` (папка `Sources/Tasker/TaskList`), а не SwiftUI `List`: ячейки переиспользуются, строки рисуются без автолейаута, поэтому список листает десятки тысяч строк.

- Строка как в макете «Все задачи»: значок статуса (по месту статуса в наборе типа), ключ серии, заголовок с пометкой `(+)` у повтора, справа чипы полей (по умолчанию все поля-перечисления проекта, до трёх чипов) и дата изменения. Правый клик по списку: «Сменить статус», какие колонки показывать (ключ, тип, поля, дата) и какие поля выводить чипами. Заголовка у таблицы нет, поэтому ширина колонок не настраивается, а порядок фиксирован, как в макете.
- Три вида: «По статусам» (группы со сворачиванием и числом задач в группе), «Плоский», «Дерево». Дерево грузится по раскрытию: `taskTree(levels: 1)` даёт верхний уровень, `taskTree(parentId:, levels: 1)` — детей одной задачи (`treeChildCount` говорит, есть ли у строки дети среди найденных). Задача с несколькими родителями показывается под каждым, под неосновным родителем — с `(+)`.
- Сортировка по нескольким ключам: кнопка «Сортировка» (клик по ключу добавляет ↑, затем ↓, затем убирает) и пилюли под строкой запроса. В виде «По статусам» каждая группа — отдельный список со своими страницами и точным числом задач: группы видны сразу, раскрытая группа грузит первую страницу и догружается, когда прокрутка доходит до её конца, свёрнутая не грузится. Заголовок группы закрепляется вверху только пока листаются задачи раскрытой группы; следующая группа выталкивает его, а у верхнего края и среди свёрнутых групп закрепления нет.
- Вид, сортировка, колонки, раскрытые задачи и свёрнутые группы запоминаются для каждого проекта (`UserDefaults`, ключ `taskList.<id проекта>`).
- «Найдено N» справа в строке запроса; сама строка запроса — TSK-190, она встанет в `TaskListQueryBar(model:query:)`, а фильтр передаётся в `TaskListModel.filter`.
- Страницы по 200 задач догружаются, когда до конца списка (или группы) остаётся меньше 60 строк. Живое событие перечитывает только страницы до видимой строки (до шести запросов одновременно); если порядок строк не изменился, перерисовываются только изменённые строки.
- Смена статуса — клик по значку статуса или клавиша `S`: меню статусов набора типа задачи (цифры 1–9 выбирают статус). Значок меняется сразу, запрос идёт через REST `PATCH /tasks/{id}`; при отказе значок возвращается, а тост объясняет причину: задачу правит другой, её только что изменили, она удалена, нет прав или нет связи с демоном.
- Клавиатура: стрелки и `J`/`K` — строки, `←`/`→` — свернуть и раскрыть, `Enter` — открыть задачу, пробел — peek-панель (обе появятся в TSK-191, сейчас это обработчики `TaskListModel.onOpen` и `onPeek`), `S` — сменить статус.

Замер на 10 000 задач (`TaskListBenchmarkTests`) включается переменными окружения; с `TASKER_BENCH_PORT` он дополнительно меряет запросы к запущенному демону:

```bash
TEST_RUNNER_TASKER_BENCH=1 TEST_RUNNER_TASKER_BENCH_PORT=5793 scripts/macos-build.sh test
```

## Иконка

Исходники иконок в `Design/icon/`: `icon-dark.svg` для тёмной темы и `icon-light.svg` для светлой. Растровые копии лежат в `Sources/Tasker/Assets.xcassets`: набор `AppIcon` (светлая, все размеры macOS) и наборы `IconDark`/`IconLight`, между которыми приложение переключает иконку в Dock вслед за темой системы.

## Окно

Рамка каждого окна хранится вместе с его вкладками и восстанавливается при запуске; системное восстановление окон отключено, чтобы источник правды был один. Второй экземпляр не запускается: повторный запуск выводит окно уже работающего.

## Создание задачи

Окно создания — лист поверх окна своей вкладки в раскладке полной карточки: слева название, описание и блок связей (высоты делит перетаскиваемый разделитель), справа тип, статус, поля типа и серии. Обязательные поля проверяются до отправки, ошибки видны в окне. ⌘Enter сохраняет, Esc закрывает (с вопросом, если что-то введено).

Задача и связи создаются одним запросом `POST /api/projects/{id}/tasks` (поле `links`): если связь не легла, задачи нет.

Точки входа: кнопка в верхней панели списка, «Файл → Создать задачу» (⌘N), «Подзадача → Создать новую подзадачу…» в карточке (родитель подставляется). Координатор `TaskCreationCoordinator` свой у каждой вкладки; палитре команд достаточно вызвать `present(parent:series:)` у координатора активной вкладки.
